## 二、临界分布过滤：为什么错

### 2.1 想做的问题

全量样本平均时，"任何出牌都能做成"与"任何出牌都打不成"的世界对候选差异贡献为零，似乎会稀释关键信息。于是设想：只保留"有输有赢"的样本。

### 2.2 数学上它分三种口径，结论完全不同（方案文档证明过，但当时没引导决策）

- **make_rate（做成率）**：过滤是**无损充分统计量变换**——平凡世界差分为零，剔除后排序不变。开了等于没开，纯空转。
- **avg_tricks（平均赢墩）**：过滤**主动丢弃了超墩幅度信息**，把目标重定向为"只在会定生死的世界里平均"——这是 MP 思路，与项目默认 IMP 目标冲突。
- **imp（期望IMP）**：IMP 表在必要墩附近跳跃最大（做成 vs 宕差 5~7 IMP，超墩仅 ~1 IMP）。**IMP 计分制本身已经是"稳健优先"的实现**，过滤再叠加只会损失稳定超墩的 IMP，净负。

### 2.3 教训

1. **一个开关挂着多个计分制，必须逐个口径论证净收益**。"叠加在不影响口径之上"不等于"对各口径都有益"。
2. **"剔除平凡样本"听起来像工程提速，实际是目标重定向**——它悄悄把"全局期望"换成了"做成边界期望"，而这个语义没有老板（用户）确认。
3. **已上线功能也能因论证撤下**。评判标准是"它真正提供了什么立场、值不值这个复杂度"，而不是"已经写了多少行"。

## 三、飞牌感知：为什么需求本身不成立

### 3.1 想解决的问题

引擎从不飞牌 / 飞牌选牌不稳定。设想：识别飞牌结构（镜像对、敏感牌），用保底优先/低张 tie-break 干预决策。

### 3.2 关键推理链（用户主导，逐步收敛）

1. **DDS 是给定世界内的最优解**——世界确定时，飞/不飞自适应，飞牌价值已被 DDS 隐含计入。不需要"教引擎飞牌"。
2. **飞牌难在"信息"，不在"选择"**——关键张（如 ♦K）在谁手里未知时，世界集 50/50，飞/不飞期望相等，选哪边都不亏（也无解）。
3. **唯一正解是"关键张位置推断"，而它在约束里**：
   - 防守方争叫约束（1 阶 8+/5+、2 阶 11+/6+、争叫位 pass ≤7）
   - 叫牌承诺 HCP 区间 + 否定推断 + HCP 守恒
   - 这些约束足够准确时，**采样过程自然排除不合适的归属**——♦K 只会落在账本允许的那家，DDS 自动飞出。约束不够的地方，本就不该赌（50/50）。
4. 因此：**"识别飞牌→干预决策"所有变体（镜像对、敏感牌、保底、低张 tie-break）都是多余的**。剩下的只有解释层（面板说"这里在飞 Q"），而那是显示需求不是决策需求。

### 3.3 教训

1. **先问"问题到底在哪一层"**。飞牌最初被当作"决策层缺陷"，实际是"采样信息层缺陷"。层找错，方案必然复杂且无收益。
2. **"识别 X"不等于"需要 X 的检测器"**。当底层引擎已被证明最优时，新增识别层只可能做两件事：报告（hello 文案）或 tie-break（锦上添花）——都不值得为它重构决策骨架。
3. **约束生成是唯一值得持续投入的杠杆**（叫牌约束、否定推断、HCP 守恒），它直接决定采样世界的正确性，从而决定 DDS 的结果。投入优先于此处的任何"打牌启发式"。

## 四、通用教训（跨两项目）

1. **数学反例要早做**。临界过滤的"对 make_rate 无损 / 对 imp 有损"在 v1.67 方案文档里就写出来了，但直到用户追问才被当成"该不该做"的依据。写进方案的数学结论应当同时回答"那还做不做"。
2. **命名混乱是症状不是病**。「临界」一词同时用于世界过滤与牌识别时，暴露的是两个概念（分歧世界 vs 敏感牌）没有各自独立的论证。概念先立，命名自来。
3. **不要为了"已有代码"保留功能**。两个开关默认关闭、无害存在——但无害不等于无负担：配置面、接口链、localStorage、文档、测试都要维护。判断标准是立场与收益，不是删除成本。
4. **用户的一句话值得全盘重估**："如果做好约束生成，加上 DDS 本身的能力，足够打出飞牌的策略。"(2026-08-26) 这比几个月打牌引擎补丁更能指导方向。

## 五、留下的正确方向（参考，非承诺）

- 打牌引擎的改进重心：**防守方争叫/开叫约束进采样**（含否定推断、HCP 守恒、争叫位 pass 上限）——验证 `extract_constraints_from_bid_history → sampler` 链路是否完整。
- 飞牌处理产物（如相关）应只落在**解释层**：识别存在飞牌结构并展示给玩家，不干预选牌。
- 若未来要处理"关键张位置推断"，落点**必须是采样约束**（软/硬分级注入），不是决策干预。
