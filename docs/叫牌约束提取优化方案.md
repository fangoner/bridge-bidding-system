# 叫牌约束提取优化方案

**创建日期**：2026-08-20
**关联**：`bridge/mcts/bid_constraint_library.py`、`bridge/play_service.py`、`llm/prompts.py`、`llm/xr_prompts.py`、`main.py`
**状态**：实现已完成（通道B 修复 + 通道A 落地，待实战验证）

---

## 一、背景与问题

打牌采样的叫牌约束来源有两类矛盾诉求：

1. **自叫牌流程的牌局**：叫牌阶段 LLM 已产出了**体系一致、信息完整**的点力/花色说明，本应直接复用。
2. **截屏 / 图片 / 历史记录导入的牌局**：没有自牌过程，只有**裸叫牌序列**，无任何含义文本，必须靠通用规则推导。

当前实现的问题：

- **通用自然规则库**（`extract_constraints_from_bid_history`）是"自然体系骨架"，对 JF/新睿**不做约定级差异化**；`system` 参数只影响 pass 否定推断的少数阈值，且调用处 `play_service.py:743` 硬编码 `system=SYSTEM_JF`。
- **含义文本解析**（`_parse_constraints_from_meanings`）本意是"复用叫牌阶段输出、免二次 LLM"，但其正则**只认 `HCP` 关键词与花色符号 `♠♥♦♣`**，认不得 `点 / 草花 / 黑桃 / X张以上 / 至少 / 至多 / 括号` 等真实措辞。于是最有价值的体系含义（如 `12-21点`、`逼叫一轮`、`联手25点`）解析出来**几乎为空**，被规则库顶上，等于"想用但没解析出来"。

---

## 二、总体设计：约束来源"双通道"

约束来源完全由 `bid_meanings` 是否携带结构化约束段决定，与牌局来源无关，无需额外标志：

| 场景 | 输入 | 约束来源 |
|---|---|---|
| 正常叫牌流程生成 | `bid_meanings` 含结构化约束段 | **通道A**：解析结构化累计约束（单调收紧兜底） |
| 截屏 / 图片导入 / 历史记录 | 只有裸叫牌序列，`bid_meanings` 为空或无结构化段 | **通道B**：原 `extract_constraints_from_bid_history` 规则库 |

**通道判定粒度**：按"家"逐个判定。

- 某家有结构化段 → 该家走通道A；
- 某家缺失结构化段 → 该家回退通道B；
- 整体无结构化段 → 全量通道B，行为与现状完全一致（向下兼容）。

**入参边界不变**：打牌阶段仍只吃 `bid_history` + `bid_meanings` 两个入参；结构化段只是 `bid_meanings` 里新增的一种编码，老记录 / 外部导入天然兼容。

## 三、通道B：规则库（现状 + 今日已修复）

通道B 作为**通用兜底**，在无逐步信息时按规则推导各家点力范围与花色承诺。以下为今日已完成的修复（已合入）：

### 3.1 第三次及以后叫牌不再收紧约束（"不超过两次叫牌"）

**规则**：同一位置的前两次（实质）叫品已把点力 / 张数范围锁定。**第三次及以后**的冲局 / 止叫 / 竞叫只是终止或延续进程，**不逆转**已确立的范围。

**修复**：`get_rebid_constraint` 前新增 `is_third_plus_rebid` 判断（该位置此前实质叫品 ≥2 时），直接保留既有约束，不再 `get_rebid_constraint` 逆向收紧。

**示例**：
```
北1♠ - 南2♥ - 北2♠ - 南3♠ - 北4♠
```
- 北前两次（1♠ 开叫、2♠ 平叫原花）已锁定 **12-15 点、♠6+**。
- 北 4♠ 是第三次叫牌 → 不再收紧。修复前 4♠ 被判定为跳叫、强行套 16-18 点，与 2♠ 平叫的 12-15 取交集成**空区间**，导致约束异常。

### 3.2 竞争性叫牌下跳叫 / 重叫原花降级

**规则**：对方已做出实质叫品（竞争性场景）时，跳叫 / 重叫原花**不适用强档 16-18**，降为平叫档 12-15；竞叫重叫原花到高阶（如 4♥）只要求 ≥5 张（而非 6+）。

**示例**：
```
(南)1♥-(西)pass-(北)2♦-(东)2♠-(南)X-(西)pass-(北)3♥-...-(南)4♥
```
- 北 3♥、南 4♥ 均为竞争性叫牌 → 12-15 点，不再误判 16-18。
- 北 3♥ 只要求 ≥5 张♥，不强制 6+。

### 3.3 其它已合入修复（一并纳入本方案）

- `prompts.py` / `xr_prompts.py`：**逼叫 ≠ 逼局**——唯有约定文字明确"逼局 / 逼进到局"才强制成局；仅"逼叫"不得硬推 5 阶低花冲局。
- 打牌决策 `avg_tricks` 回归纯平均赢墩，清除 maximin 死代码（见提交 `496423d`）。

## 四、通道A：叫牌阶段输出结构化约束

### 4.1 语义定义（核心）

**`叫品约束` = 该位置下这个叫品之后，累计至今的自身承诺**（点力区间、花色长度、均型与否）。**不是**本轮新增的那一段差异。

### 4.2 更新规则

同一位置内，约束相对上一轮**只能收紧或不变，绝不放宽**——这是叫牌的结构性不变式（见 4.4 兜底）：

- **描述性 / 收紧性叫品** → 更新区间。典型触发：
  - 再叫新花（尤其**逆叫**）→ 点力下限抬升；
  - 跳叫 / 强加叫 → 点力或长度收紧；
  - 花色长度加码（如 2♦ 承诺 D≥4，3♦ 承诺 D≥5）。
- **不影响点力 / 长度的叫品** → **保持原字段不变**。典型触发：低限平叫原花、简单加叫、无将续叫、止叫、pass。

**示例**：
| 轮次 | 叫品 | 约束字段（累计） |
|---|---|---|
| 南 | 1♣ | `HCP12-21\|C3+` |
| 北 | 1♠ | `HCP6+\|S4+`（应叫） |
| 南 | 2♦（逆叫） | **更新**为 `HCP16-21\|C5+\|D4+\|非均` |
| …后续 3♣ 低限停叫 | | **保持** `HCP16-21\|C5+...` 不变 |

### 4.3 落地改动

1. **`llm/prompts.py`**：三处输出模板（首轮 / 再叫 / 人工）在 `叫品含义` 后新增 `叫品约束` 字段，给定格式与示例，并把**体系强制点挂钩**（如 JF `1♦-(1♠)-2♥ 逼叫一轮` → `HCP12+|H5+`）。
2. **`llm/xr_prompts.py`**：复用共享模板，仅注入新字段格式说明。
3. **`main.py` `process_bid`**：把 `叫品约束`（连同累计语义）拼入 `bid_meanings`，保存该轮结构化段。
4. **`bridge/play_service.py` `_parse_constraints_from_meanings`**：优先解析结构化段；失败回退现有正则 / 规则库。

### 4.4 单调收紧的硬性兜底

不依赖 LLM 自觉——解析出该位置本轮累计约束后，与**上一轮同一位置已有约束取严格交集**再存储：

- 点力：`min=max(旧min, 新min)`、`max=min(旧max, 新max)`；
- 花色 `suit_min` 取大、`suit_max` 取小；
- 若 LLM 本轮区间反而更宽（如 16-21 → 12-25），**丢弃违反不变式的部分**，保留收紧状态。

复用现有 `_merge_constraints` 的"取交集"逻辑即可（旧值是上一轮已累计的同位置约束）。

### 4.5 `叫品约束` 格式规范（语法）

`叫品约束` 为**单行紧凑串**，解析器按 `|` 分段，每段形如 `键值`。规范限定，避免自由措辞歧义：

```
叫品约束 := 约束段 ('|' 约束段)*
约束段   := HCP段 | 花色段 | 牌型段
HCP段    := 'HCP' 下界 ['-' 上界]        ; 缺上界=无上限；示例 HCP12-21 / HCP16+ / HCP≤7
花色段   := 花色代码 长度 [('+'|'-')]    ; '+'=至少，'-'=至多，裸数字=精确
花色代码 := 'S' | 'H' | 'D' | 'C'        ; 一律用字母，避免中文/符号歧义
牌型段   := '均型' | '非均' | '单缺'      ; 可选
```

**约定**
- 花色段只写**该叫品新承诺 / 累计明确**的最小（`+`）或最大（`-`）长度；无承诺不写该花色。
- 点力与张数均为**个人**承诺，不含"联手合计"。
- 本轮若与该位置上一轮一致，`叫品约束` **原样输出**（不变式由 4.4 兜底，LLM 保持一致即可）。

**各叫品类型规范示例**（均为该位置累计约束）：

| 类型 | 叫品 | `叫品约束` |
|---|---|---|
| 开叫 | 南 1♦ | `HCP12-21\|D4+` |
| 逆叫 | 南 1♣后 2♦ | `HCP16-21\|C5+\|D4+\|非均` |
| 应叫 | 北 1♠ | `HCP6+\|S4+` |
| 应叫（二盖一） | 北 2♥ | `HCP11+\|H5+\|不逼叫` |
| 强冲局（第三次+） | 北 4♠ | `HCP12-15\|S6+`（保持 2♠ 状态） |
| 无将开叫 | 南 1NT | `HCP15-17\|均型` |
| 争叫 | 西 1♠ | `HCP7+\|S5+` |
| 弱二 | 西 2♦ | `HCP6-10\|D6+` |

解析器只认上述小集合，不匹配的段跳过；存在 `HCP` 段而无花色段时，只收紧点力。

## 五、风险与边界

- **LLM 偶漏 `叫品约束`**：字段缺省 + 回退旧路径，只丢增量不破坏正确性。
- **"联手 25 点 / 止张分析"是合计**：结构化段只收**个人承诺**（点力下限 / 花色长度），不把联手数误当个人 HCP。
- **与通道B 仍是"取交集"**：结构化硬约束与规则库兜底同为收紧方向，最终在采样层一致收紧。
- **token 成本**：新增字段会略微增加每轮叫牌输出 token，需观察。

分两场景验证：

1. **自牌流程牌局 → 通道A**：打印每家解析出的约束，确认与 JF 含义吻合：
   `南1♦ 12-21/D≥4`、`北2♥ 12+/H≥5`、`南3♣ 12-14/C≥3`、`北3NT 25+止张`。
2. **截屏 / 图片导入牌局（无含义）→ 通道B**：行为与现状一致，采样约束仍由规则库提供。

并验证单调收紧不变式：人为让 LLM 输出更宽区间时，约束仍保持上轮收紧状态。
