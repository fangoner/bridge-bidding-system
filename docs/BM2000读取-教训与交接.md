## 三、Data 文件格式（已核实，可靠）

- 每副牌以标记 `st||nt||sk||md|` 开头：
  ```
  st||nt||sk||md|<手牌串>|mb|...|mb|...|...|cb|..|cg|..|cr|..|hs|..|hc|..|at|..讲解文字..
  ```
- 一段从当前标记一直延伸到**下一个标记**。
- 有效判断：标记后首段（`|` 之前）第一个字符 ∈ `"1234w"`，且后续含 ≥3 个 `mb|...|` 令牌。
- 手牌串解析（`_bm_convert.decode_hands`）：
  - 首位数字=起始座位：`1=S, 2=E, 3=N, 4=W, w=W`；然后按顺时针（`CCLK`）依次填 4 家，逗号分隔。
  - 旋转映射：`"1":南西北东`，`"2":东…`，`"3":北…`，`"4":西…`，`"w":西…`。
- 叫牌：`mb|X|` 令牌序列；`p` 为 pass。定约=最后一个数字叫品。

### 关键结论：**直接从 marker 渲染全部牌局是可行的**

遍历每个 Data 的**全部** marker，逐个渲染，得到：

| level | 有效牌局数 |
|-------|-----------|
| L1 | 183 |
| L2 | 96 |
| L3 | 96 |
| L4 | 96 |
| L5 | 66 |
| **合计** | **534** |

只有 **3 个** 假阳性 marker（首段像手牌但实际不是牌局）。即：**"读全所有牌局"这件事本身已解决**，534 副牌的四家手牌、叫牌、定约、首攻都能可靠还原。

## 四、Index 文件格式（已核实）

- 结构：`名字` + `\x00` + **3 字节大端偏移**，循环。
- 名字是真实课程名：`A1–A36`、`B1–B30`、`C1–C30`、`D1–D30`、`M1–M117`。
- 另含 `<课程>.<牌局>` 引用项，例如 `CARE1.A2`、`DUCK1.A21`、`SUIT1.A7`、`QINFR100.A33`、`TRUMP300.D11`。

## 五、走过的弯路（教训，重点）

> 这一节是本文件存在的核心理由。新会话务必先读这里，避免重蹈。

1. **最大错误：假设 Index 的 offset 是 Data 的字节偏移。**
   初版 `tools/bm_import.py` 的 `at(off)` + `nearest_valid_marker()` 就建立在这个假设上 → 全盘错误：`bm_deals.json` 只有 333 副、其中 **324 副被 skip**，且映射到的 marker 与名字无对应关系。**此假设已被证伪，看到 `at()`/`nearest_valid_marker` 请直接重构，不要在其上打补丁。**

2. **Data 里根本没有牌局名字。**
   对 Data 全量搜索 `B20` / `A1` / `.LIN` / `Board` / `board`，命中数全为 **0**。名字只存在于 Index。→ 任何"从 Data 直接读名字"的方向都是死路。

3. **名字 → marker 不是简单字母序映射（反例证明）。**
   以 B20 为锚点：B20 纯名顺序号（0 基）= **48**；其手牌实际匹配到的 marker 序号（0 基）= **89**；该处 offset = **163744**；mbs = `1H p 2D p 3D p 3H p 4H p p p`；按序号取名字得到的是 **C30**。→ **字母序/顺序号映射不成立**（probe22）。

4. **但名字可能按"某种顺序"对应（线索未闭合）。**
   Index 的 `<课程>.<牌局>` 引用项与对应 marker 的讲解文字**存在相关性**（probe23）：`A3→TRUMP18` 命中 "trump lead"；`A7→SUIT1`；`A21→DUCK1`；`A30→ENTRY1`；`A33→QINFR100`；`A2→CARE1`。→ 说明名字或许能恢复，但**具体顺序仍未知**（probe24 尚未运行，本文件生成时）。

5. **不要跨 level 对齐同类牌局。**
   各 level 是**独立**牌局集合，跨 level 同位置对齐命中率 0%。

6. **早做锚点验证。**
   用一副**已知手牌**（B20：南家 ♠32 ♥KQJT9 ♦A32 ♣A32）做锚点，能在几分钟内否掉错误假设。前一会话在跑了 20+ 个探针后才用上锚点，代价过大。

7. **流程教训：该早说就早说。**
   用户明说"搞不定早点讲"。正确做法应是：确认"offset 假设"崩掉后立即停下来汇报，而不是继续加探针。→ 新会话请沿用：一旦连续 2–3 个探针无正向结论，立即上报并给方案选项。

## 十一、座位归属修复（2026-09-17 补记 v1.84：md 是标准 LIN 格式）

**v1.83 遗留的座位 bug**：用户实测 2-B29 南北颠倒、5-A19 庄家变东西（应只有南北）；全局统计 537 副中东西庄 199 副。

- **根因**：`md|` 手牌串首位数字被当作"起始座位 + 顺时针旋转展开"（D2S+CCLK），仅 "1"→南 碰巧正确。真实语义是**标准 LIN 格式**：首位数字 = dealer（1=南 2=西 3=北 4=东，"w"=南），手牌四段**固定按 南、西、北、东** 顺序，与 dealer 无关
- **铁证**（5-A19）：讲解 "West has shown an 8 card heart suit with his opening 4 heart bid"——旧西家仅 ♥32，而固定西南北东序的段2（南位）恰为 ♥KQT98765 八张套；且 "West leads the HK" 的 K♥ 也在该手。修正后叫牌 (西)4♥-(北)X-(东)p-(南)5♣ 完全自洽（西 8 张 ♥ 开 4♥、北 18 HCP 惩罚加倍、南 7 HCP ♣QT432 牺牲叫）
- **叫牌截断**：讲解流会把 what-if 假叫牌混入 `mb|` 令牌（如 3-C9 的 `6H p p p` 后又现 `2C P 2D...`）——正确序列 = 截到 `ha|` 令牌 + 有数字叫品后遇 3 连续 pass 终止
- **修复后验证**：537 副**全部南庄**（BM2000 是南视角做庄训练软件）、529 副首攻全西；讲解 "Xxx leads ... against" 首攻文本一致率 443/443；.Fan 完整模拟器（跟牌强制+将吃+赢家轮转，v1.83 用的简化轮转在将吃墩会错位）join 49 命中、0 多重命中、0 错误首攻方向
- **教训**：LIN 派生格式的字段语义应先对照标准 LIN 规范（`md|<dealer><南西北京>`），而不是从单个锚点反推旋转规则——单锚点（"1"=南）验证通过的映射可能只是碰巧
