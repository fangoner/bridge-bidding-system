# 新睿体系树格式转换方案

## 目标

将《新睿桥牌二盖一体系》（326 页扫描书）转换为与 JF 体系相同契约的树格式 Markdown 文档 `新睿实战_二盖一体系.md`，供系统未来作为第二叫牌体系接入（本阶段只做文档整理与验证，不改生产代码）。

## 源材料

| 文件 | 用途 |
|---|---|
| `书籍/新睿桥牌二盖一体系.md` | OCR 全文（13596 行），花色符号基本正确，部分表格列交错 |
| `书籍/新睿桥牌二盖一体系.pdf` | 扫描件 + OCR 词坐标层，`scripts/xr_pdf_rebuild.py` 用于交错表格的坐标重建核对 |

全书 13 章：1 总纲 / 2 1♣ / 3 1♦ / 4 1♥ / 5 1♠ / 6 1NT / 7 2♣ / 8 2NT / 9 阻击 / 10 满贯 / 11 防守 / 12 首攻信号 / 13 约定叫注释。核心内容为约 474 个编号表格（"表X-Y 序列 后续"），表格标题=叫牌序列前缀、行=候选叫品分支、说明列引用后续表号构成树边。

## 目标格式契约（与 JF 一致，反向工程自 knowledge/loader.py）

1. **分段**：段之间以 2 个空行分隔
2. **关键词**：段的**前 3 行整行文本** + 段内所有编号行（`^\d+\.\d+(\.\d+)*\s` 开头）；检索为整行精确匹配（`JFRetriever.retrieve`）
3. **段类型与内容格式**：
   - `花色开叫`（开叫条件）：首行 `花色开叫`，正文为缩进 0 的 `1C：…` 平铺行（`extract_first_level_bids` 提取）
   - `1C开叫`/`1D开叫`（应叫人决策）：首行 `1C开叫`，正文为 `1C-1D：…` 平铺行（`extract_response_bids` 按 `^1C-\d[CDHSNT]：` 提取）
   - `X-Y` 树段（开叫人再叫及后续）：前 5 行内有独立行 `1C-1D`；正文为 `├1H：说明` 树行，子层前缀 `│-----`；同级可选叫品用 `/`（如 `├3S/4C：`）。2 个叫牌时取第一层（`extract_first_level_bids`），3+ 个叫牌时按树导航（`parse_content_to_tree` + `navigate_tree_by_bids`）
   - 干扰/兜底段（`对方一阶争叫`、`成局与满贯` 等）：非结构性，仅作 fallback 原文注入 LLM，无格式要求，首行为关键词即可
4. **叫品规范**：大写 `1C-7NT` / `X` / `pass`；树行必须可被 `extract_bid_from_line` 解析

## 工具链（scripts/）

| 脚本 | 功能 |
|---|---|
| `xr_slice_source.py` | 按章/节/表标题切分 OCR md 到 `scripts/xr_data/source_slices/` 供整理核对 |
| `xr_pdf_rebuild.py` | 按表号定位 PDF 页，按词坐标（y 聚类/x 分列）重建交错表格行，输出核对文本 |
| `xr_build_tree.py` | 从 `scripts/xr_data/tables_built.json`（结构化行数据）确定性渲染目标 md（树缩进由脚本生成，避免手写缩进错误） |
| `xr_validate.py` | 只读验证：段可建树、叫品合法、样例序列关键词命中、subsequent_bids 非空、覆盖报告 |

`tables_built.json` 结构：`{"keyword", "type": "xy_tree/flat/response/prose", "title", "root", "children": [{"bid"/"bids", "points", "desc", "children"}]}`。

## OCR 清洗规则

- 点力：`12≥17`→`12-17`（"≥"夹在数字间实为波浪号），`~18`/`≥18`→`>=18`
- 花色：`令`→♦，`今/会`→♠，`曾/萼/¥`→♥，`＊/*/+/ft/tft/4ft`→♣（按叫品合法性校验消歧）
- 错字：`廿`→叫、`贵任`→责任、`I 厂`→商 等
- 叫品：`l`→`1`、`21ft`→`2♣`、`2-t-`→`2♣`，一律大写规范化

### 核心瓶颈与对策

1. **TABLE_SEQ 手写不可扩展**（当前仅 68 个表硬编码）
   - 对策：从**附录一"叫牌过程索引"（L12658 起）**自动解析 `表号→叫牌序列` 映射，生成 `tables_seq.json`。该索引虽 OCR 混乱，但表号+序列+说明三列结构可用词坐标重建（复用 xr_pdf_rebuild.py）。
   - 兜底：seq 未知的表，用表内行叫品+相邻表序推导，仍无法确定时标记 `SEQ_MISSING` 进人工核对清单。

2. **tables_ch2.json 仅含第2章**
   - 对策：xr_build_tree.py 改为按章节加载 `tables_ch{2,3,4,...}.json`（或合并为 `tables_all.json`），main 的根树从硬编码 3 个改为**按根表自动发现**（应叫表=每章首表，后续树=应叫后各分支）。

3. **跨章引用**（如 2-54/55 指向表2-54/55 实为 1C-1D 后跳叫，表4-1 等被第13章引用）
   - 对策：链接解析时允许跨章（表ID全局唯一），visited 防环已支持。

4. **OCR 噪声规模放大**（第2章 80 表已暴露 46 处点力缺失、A类合并等）
   - 对策：试点阶段总结的清洗规则（SUIT_FIX/DESC_FIX/CLUB_OCR/no-bid修复）已通用化，全量复用；每章转换后跑 `xr_scan_review.py` 生成该章核对清单。

## 干扰表/防守表"括号关键字"设计（2026-08-16）

### 系统序列与括号的约定（硬约束）

- **系统内部叫牌序列一律无括号**：`parse_bidding_sequence` 会剥离所有 `()`/`（）`；`extract_retrieval_keyword` 同样把括号替换为空。因此系统侧拿到的真实序列形如 `1C-X-1D`、`1C-1D-1H`，不含任何括号。
- **敌我判定靠位置而非括号**：`parse_bidding_sequence_with_positions` 保留位置（接口侧为 `(S)1C-(W)pass-(N)2C` 前缀格式）。以"视角"（下一个叫牌者）为基准，我方=视角方及其同伴，敌方=另外两家。**敌方叫品在提取关键字时自动加括号，我方叫品不加括号。**

### 关键字格式

| 序列形态 | 括号关键字 | 例表 |
|---|---|---|
| 我方开叫被敌方加倍 | `1C-(X)` | 表2-69 |
| 我方开叫被敌方花色争叫 | `1C-(1D)` / `1C-(2C)` | 表2-70、2-71、2-72 |
| 我方开叫被敌方 NT 争叫 | `1C-(1NT)` | 表2-75 |
| 敌方约定性争叫扣叫 | `1C-(2C)`（迈克尔斯）/ `1C-(2NT)`（特殊2NT） | 表2-76、2-77 |
| 我方开叫→应叫→敌方再参与 | `1C-1H-(X)` | 表2-78、2-79、2-80 |
| 敌方开叫、我方介入（第11章防守） | `(1C)-1D` / `(1H)-X` | 表11-1..11-31 |

要点：
- 括号只包敌方叫品，我方叫品保持无括号，与系统内部序列一致。
- `pass` 不参与括号（我方 pass 是正常轮转；敌方 pass 不改变后续结构）。
- 文档段首行即关键字（带括号），正文为响应叫品树行（我方叫品，无括号）。

### loader 未来匹配方案（接入阶段实现，本阶段仅记录）

当前 `is_structural_convention`/`parse_content_to_tree` 的 root 识别正则 `^[1-7](?:[CDHS]|NT)-[1-7](?:[CDHS]|NT)$` 不认括号，需扩展：
1. root 段首行识别正则允许括号：`^(?:\([1-7](?:[CDHS]|NT)\))-?[1-7](?:[CDHS]|NT)...` 等通配括号的序列形态。
2. `extract_bids_from_sequence` 已能剥离括号，得到无括号 bid 列表，可直接用于 `navigate_tree_by_bids` 走树。
3. 匹配时：用无括号真实序列 + 位置信息，在敌方叫品处自动加括号生成候选关键字，再整行精确匹配 doc 段首行（`JFRetriever.retrieve`）。
4. 树子行叫品全部是我方叫品（无括号），`extract_bid_from_line` 无需改动。

### 干扰表 OCR 现状（2026-08-16 实测）

探测 `xr_probe_interference.py` 显示：第2章干扰表（2-69~2-80）**OCR 跨表污染严重**——每张表按词坐标解析出的条目大量混入相邻表内容（如 2-69 的 30 条含 2-70/2-71/2-78 等表行），描述乱码（`1♣一(X)后续说明`、`1I支待性加倍` 等）多。**程序化自动建树会产生垃圾，不可行。**

处置：干扰/防守表**不自动建树**，保留在兜底段平铺；待人工逐表对照 PDF 原文核对，用 `MANUAL_SEQ` 注入括号序列 + 必要的手工条目修正后再挂树。括号序列格式按本节约定。
