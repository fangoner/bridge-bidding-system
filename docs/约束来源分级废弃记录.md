# 约束来源分级废弃记录（v1.79 重大BUG）

> 2026-09-15。重大BUG复盘 + 修复决策。关联文件：`bridge/mcts/constraints.py`、`bridge/mcts/sampler.py`、`bridge/mcts/bid_constraint_library.py`、`bridge/play_service.py`（`_rebuild_bid_constraints`/`_build_constraint_from_structured`/`_merge_constraints`）。

## 1. 问题现象

复现某副牌（4♥南，北 1C / 东 1S / 南 2H / 北 3H / 南 4H），北家（明手）出 ♠K 时，DD 引擎 350 个采样世界中东西两家的黑桃分配为**纯均匀**（东 0~5 张均有，峰值东 3 张 ~40%）。

但东家叫过 1S（承诺 ♠≥5），若约束生效，东♠ 应被锁在 ≥5（未知黑桃仅 A987T 五张 → 东拿满 5 张、西 0 张）。违反直觉的均匀分布暴露：**约束没有参与采样**。

## 2. 根因链（三层接力）

### 2.1 白名单诞生（Phase 0a，`3261457`）
`_HARD_SOURCE_PREFIXES` 六条前缀：
`hard_coded* / meaning_parsed / convention_* / cue_bid / overcall_* / unusual_nt`

当时约束只来自两处，全部命中白名单：
- 规则库 `bid_constraint_library.py` → `hard_coded*`/`convention_*`/...
- 含义正则 `_build_constraint_from_meaning_free` → `meaning_parsed`

**这个时代约束是真生效的。**

### 2.2 v1.65（`48d9ab0`）：引入白名单外来源
约束"来源双通道"，新增通道A：
- `_build_constraint_from_structured` → `inference_source="structured"`（外部）

规则库仍并存（hard_coded 兜底部分家），白名单漏配被掩盖。

### 2.3 v1.66（`8062d08`）：断裂点
约束生成重构：
- 弹窗统一入口：seed payload → `_rebuild_bid_constraints` → `inference_source="structured"`
- LLM 转换：`generate_constraints_from_meanings` → `_build_constraint_from_structured` → `"structured"`
- **移除规则库接入** （`extract_constraints_from_bid_history` 不再被主代码调用）

此后约束来源 100% 是 `structured`（合并后 `merged`），白名单一个都对不上 → `filter_hard_constraints` 恒空 → 采样退化为纯均匀。

### 2.4 假象掩盖（为什么近一个月没发现）
三层打印都"看着像约束在工作"，但**没有一层看过滤后结果**：
1. `[DD] 约束已应用: N家, {...}` —— 打印的是 `_get_bid_constraints()` 未过滤返回
2. dd_search 日志 `constraints=True(N)` —— 只查 `bool(self.sampler.constraints)` 字典非空
3. 过滤后为空 → `active_constraints` 空 → 直接 `_sample_uniform`，**连 L0/L1/L2 降级日志都不出现**（降级日志只在"有约束但验证失败"时打）

## 3. 修复方案（用户定调："直接用约束，删白名单"）

白名单保存旧体系，其区分对象（可靠承诺 vs 推理猜测）已随规则库退役而消失；当前约束 100% 来自 LLM 转换/用户确认 seed，均为可靠承诺。**删除来源分级，所有约束一律按硬约束验证**。

- `constraints.py`：删 `_HARD_SOURCE_PREFIXES`/`_IGNORED_SOURCES`/`is_hard_source`/`is_ignored_source`/`filter_hard_constraints`；`validate_hard`/`validate_relaxed` 去 source 跳过
- `sampler.py`：`sample()`/`sample_n()` 直接 `self.constraints`
- `bid_constraint_library.py`：文件头 deprecated 标注（研究资产，不接入）
- `test_sampling_constraints.py`：清 import

## 4. 约束来源现状（勿再分级）

| 来源 | 产生处 | 说明 |
|---|---|---|
| `structured` | seed payload（`_rebuild_bid_constraints`）/ LLM 结构化转换（`_build_constraint_from_structured`） | 主来源 |
| `merged` | 同位置多叫品 `_merge_constraints`（如北 1C→3H 取更严格承诺） | 正常机制 |
| `relaxed` | 验证链内部降级 `relax_constraint` | 不参与过滤 |

## 5. 行为影响

- 修复后约束重新参与采样：东 1S 样本中东♠ 固定 5 张（350/350 验证通过）
- **对飞牌介入的影响**：飞牌探针 Δ、结构判定、启动门控、接应威胁全部消费采样世界 `candidates`——世界从均匀变为符合叫牌承诺，飞牌判断更真实（详见 CHANGELOG v1.79 与飞牌讨论记录 §9 上下文）
- 引擎行为级变更：DD/αμ 出牌决策依据的分布改变，需实测回归

## 6. 教训（勿再犯）

1. **引入新数据来源（source 名）必须同步更新消费端白名单/过滤器**——v1.65 引入 `structured` 忘了扩白名单 → v1.66 切源后全线失效
2. **别给"过滤前/非空"打印当成功**——`约束已应用 N家`/`constraints=True(N)` 都不代表约束真参与验证；需要一层"过滤后实际生效家数"或直接断言 active_constraints 非空
3. **架构切换（移除规则库）时必须清理其关联的失效机制**——v1.66 移除规则库却没删白名单，白名单成为悬空过滤
4. **"直接用约束，删多余分级"比维护白名单更符合现状**——分级只在有区分对象时才有意义

## 7. v1.80：约束来源规则定死——[AI] 行一律不转译（2026-09-15）

> 本档是约束相关问题的合集记录，v1.80 追加本节。与 §2（结构失效）是**两个独立问题**，勿混淆：
> - §2~§6 讲"约束进了采样却被过滤"（来源分级白名单失效）——v1.79 修复
> - 本节讲"不合格的来源进了约束生成"（AI 模拟含义被转译成硬约束）——v1.80 修复

### 7.1 问题

v1.79 修复后实测截屏牌局，发现约束转换 LLM 把 **[AI] 来源的约定叫**（扣叫）也提取了：东 3H 含义文本（新睿二盖一模拟补全）写"对开叫人♠有配合（通常至少3张支持）"，被转成 `♠≥3` 硬约束。双重错误：

- **叫牌方向误判**：东是西的同伴、西已争叫 2♥，东 3♥ 本应是♥加叫（→♥≥3），含义却解读成"对♠扣叫"（叫牌侧 LLM 误读）
- **违反前端约定**：`web/src/App.jsx:2150` 注释明确"后端仅对非AI来源行做约束转译"，后端 prompt 的"[AI] 约定叫可提取"例外是后加的未对齐产物

### 7.2 决策（用户定调，勿再改回）

> "改为 AI 一律不转译。要有明确记录，不要后面又搞不清楚。提高 AI 叫牌能力过一段时间再做。"

- **约束唯一可信来源 = 叫牌阶段真实产物**：[JF]/[XR] 含义（人叫牌或 AI 实叫的真实叫品含义）
- **[AI] 行（模拟补全/解释性含义）一律不转译**：无论自然叫还是约定叫（扣叫/4NT-5NT/斯泰曼等）都不提取，constraint 输出空字符串
- 截屏牌局 = 新睿二盖一模拟补全含义 = 全 [AI] 行 → 全部跳过，约束为空（尊重引擎采样），不再产出 ♠≥3 类假约束
- 提高 AI 叫牌能力（让 [AI] 含义可信）是**独立工作**，另行评估后再调整约束策略，不在本次范围

### 7.3 实现

`CONSTRAINT_TRANSLATE_PROMPT`（play_service.py）：
- 来源过滤规则删除"仅当含义明确属于约定叫时提取"例外 → **"[AI] 行一律不转译"**
- 转译规则2 "[AI] 禁止推导 HCP"保留，注明为冗余兜底
- 与前端 App.jsx:2150 约定对齐

### 7.4 行为影响

- 截屏/人工输入/历史导入牌局（无真实含义 → 全 [AI] 模拟）约束为空，DD/αμ 采样回到无约束状态——**这是符合约定的回退**（宁可无约束，不用不可信约束污染采样）
- 正常 AI 全程叫牌（叫牌阶段真实产物）不受影响：真实叫品含义仍为 [XR] 标注，照常转译
