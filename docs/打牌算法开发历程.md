# 打牌算法开发历程：全景梳理

> 2026-08-29 归档。本文梳理打牌算法从 v1.32 到 v1.68 的完整开发历程、当前状态、核心教训、目前困难与可能的解决方案。信息来源：CHANGELOG.md 全量（74 个日期条目）、DEVELOPMENT.md / DEVELOPMENT_HISTORY.md、docs/ 下五份专题报告（改进打牌引擎讨论、打牌窜牌诊断报告、αμ+LLM引擎开发记录、PIMC_SAMPLING_IMPROVEMENT_PLAN、dd_card_selection_discussion、dd_sampling_optimization_plan、llm_review_effectiveness_plan、教训_临界过滤与飞牌识别的废弃）及代码现状。

## 一、开发历程（按时间线）

### 阶段 1：LLM 出牌时代（v1.32–v1.33，2026-02）

- **v1.32**：打牌功能上线，唯一引擎是 **LLM 直出**（DeepSeek 提示词决策）。
- **v1.33**：全面重写打牌提示词——已见牌张逐花色追踪、防守信号体系、庄家分析框架。这个阶段的本质问题是：**LLM 不具备精确的墩数计算能力**，出牌质量完全依赖提示词工程。

### 阶段 2：搜索引擎引入（MCTS → DD，2026-04 ~ 2026-05）

- **MCTS 引擎**：确定化（采样未知手牌）+ UCT 树搜索 + 启发式 rollout。
- **DD 引擎**：纯蒙特卡洛采样 + endplay `solve_board` 双明手评估每个候选。
- **2026-05-03 重大 bug**：`solve_board` 返回值的赢墩方向被误判（返回的是 `deal.curplayer` 所在方赢墩，而非 `deal.first`），导致 DD 出牌"等于随机"——第一次认识到**双明手求解器的语义细节能颠覆整个引擎**。

### 阶段 3：分层调度与大师级优化（v1.40–v1.48，2026-06 ~ 2026-07 中）

- **v1.40**：Tiered 分层引擎（首攻 DD+LLM 融合 / 中盘 DD 替代 MCTS / 残局 αμ 或 DD 枚举）；新增 Perfect DD 全知引擎（仅发牌练习模式）；新增人类 DD 提示。
- **v1.41 大师级七件套**：三信号关键决策检测（strategy fusion 跨度 / 候选集群 / 样本不足）、MCTS 根节点选牌修复、**BeliefTracker 粒子滤波**（60 加权粒子）、**αμ 搜索引入**（Wbridge5 算法，Cazenave & Ventos 2019，针对 PIMC 的 strategy fusion / non-locality 两大理论缺陷）、首攻 DD+LLM 融合、防守信号模型（Attitude/Count/Suit Preference）、LLM 输出校验层。
- **v1.42**：αμ 超时快速 DD 回退（截断候选走单层 DD 叶评估，快 5-10 倍）。
- **v1.43**：按牌复盘替代按墩复盘；DD Hint 预录到 trick 数据。
- **v1.45**：DD 性能全套修复——中局约束扣减法替代比例缩减、软硬约束区分（负推断/点力守恒视为软约束）、`solve_all_boards` 批量求解（分批 ≤200），600 粒子提速 5-30 倍。
- **v1.46**：复盘模式 DD Hint 与按牌回退完整重构。
- **v1.47**：DD 三连修复——明手领出 `deal.first` bug（新增 `actual_turn` 参数传递 6 个下游函数）、选牌三层分层比较（avg 显著差异 → 小牌优先 → rank 相同回退 avg 方向）、手工出牌 GUI 面板。
- **v1.48**：αμ+LLM 引擎——用 `best_vector` 把 DDS 等价的候选做三层分组（花色 + rank 区间），LLM 只在引擎无法区分时做战术选择；Prompt 系统重构（飞牌优先识别 / NT 赢墩分支 / 5 维评估 / 一致性约束 / 绝望模式）；Plan 生命周期管理。

### 阶段 4：回归论文与 DirectDDS（v1.49–v1.50，2026-07-19）

- **v1.49**：αμ M 参数语义修复（M=1 退化为 PIMC）；新建 `bridge/mcts/direct_dds.py`，ctypes 直调 DDS C 库，绕过 endplay 的 Card→PBN→Deal 转换链，**约 6 倍提速**；Bitmap 手牌表示。
- **v1.50 大重构**（净删 ~1400 行）：
  - 采样从"三步有偏生成"（shape→HCP→牌张分配）改为**均匀采样 + 分级约束验证回退链**（L1 硬约束 50 次 → L2 放宽 → L0 仅 void），对齐论文；
  - **移除 BeliefTracker**（引入仅一个月即废弃，均匀采样不需要粒子加权）；
  - dd_search 全部切换到 DirectDDS，**彻底移除 endplay 依赖**；
  - 2021 论文优化全部落地：World Cuts、Cut on Win、Maintaining Useful Worlds、Leaf Parallelization、Deep Alpha Cut、Empty Entry。

### 阶段 5：稳定性与采样攻坚（2026-07-25 ~ 2026-08-14）

- **窜牌修复**：全局单例 PlayService 被并发请求覆盖 `state.hands`，引擎偶尔返回不属于当前玩家手牌的牌 → 按 session_id 会话隔离（详见 docs/打牌窜牌诊断报告.md）。
- **DDS 并发安全**：DDS C 库非线程安全，并发调用损坏内部状态导致崩溃（`Sum 3 is not four`）→ `_dll_lock` 扩展至所有求解入口串行化；DD hint 移出请求关键路径（ThreadPoolExecutor 后台计算 + 快照）。
- **MH 采样系列修复**（08-10/11）：
  - 世界完整性：旧逻辑"先跳 void 后回填"静默丢牌，DDS 成功率 0/50 → 重写 `_sample_uniform` 逐张分配（Tier1/Tier2），保证世界永远完整，50/50；
  - MH 死锁：补花色扔高 HCP 牌跌破 `min_hcp` 来回振荡（成功率 19-43%）→ 自适应保 HCP 路径，100%；
  - 补花色保护边缘花色："补♦破♥"振荡（逆叫16+ 仅 50%）→ protected 集合，100%；
  - 可行性预检：识别"花色约束迫使 HCP 超标"，不可行场景 2.8s → 23ms/样本；
  - 稀疏性量化：紧约束下合法世界占比仅 0.004%~0.225%，回退根因是**可行解稀疏而非约束冲突** → 落地 `_sample_master_soft` 主从软约束采样（master 约束满足率 ~0.20% → 100%）。
- **αμ 残局死循环**：极深残局（每手 1-2 张）约束不可满足陷入 MH→L2→L0 回退链死循环 → ≤4 张强制精确枚举且 `constraints=None` 跳过约束验证。

### 阶段 6：计分制与约束重构（v1.65–v1.68，2026-08 下旬）

- **v1.65**：约束来源双通道（叫牌阶段结构化约束 + 规则库兜底）——后被 v1.68 取代。
- **v1.66**：计分制（IMP / make_rate / avg_tricks）贯穿候选分组与输出，`success_rate` 修正为当前方目标达成率（坐庄=成约率，防守=击垮率），修复防守方符号与排序方向全错；首攻/信号方案注册表（`bridge/play_strategies.py`，标准方案全文源自新睿自然 Rev 3.2 第十二章）；αμ 残局枚举门槛与 DD 统一（固定最后 4 墩）；前端渲染性能治理（生产构建 + CardTable memo 修复 + AIProgressContext 拆分）。
- **v1.67 → 废弃决策**（详见 docs/教训_临界过滤与飞牌识别的废弃.md）：
  - 临界分布过滤：经数学论证对 make_rate 是无损空转、对 avg_tricks 是目标重定向、对 IMP 是净负（IMP 表本身已是稳健优先实现）→ **整体移除**；
  - 飞牌感知（镜像检测 / 保底优先 / 低张 tie-break）：论证后认定**需求本身不成立**——DDS 在给定世界内已最优，飞牌难在"关键张位置推断"而推断在约束里 → **未发布即废弃**。
- **v1.68（当前）**：约束生成重构（详见 docs/约束生成优化.md）——约束统一在"确认定约与首攻"弹窗由 LLM 从完整叫牌含义文本转译生成；规则库（bid_constraint_library.py）退役为研究资产不接入系统；叫牌阶段与约束完全解耦（三个 JSON Schema 删除"叫品约束"字段）；人类叫牌检索命中必走 LLM，失败即 502 中断。

## 二、当前状态

**主力引擎 `dd_alphamu_llm`** 的分层结构：

| 阶段 | 每手牌数 | 引擎 | 说明 |
|---|---|---|---|
| 中盘 | >8 | DD（蒙特卡洛 + DirectDDS） | IMP 计分，~200 样本（100-2000 可调），纯概率选牌 |
| 残局 | ≤8 | αμ Pareto 搜索 | M=2，20 worlds（滑块 10-100），论文优化全配 |
| 极深残局 | ≤4 | 精确枚举 | 枚举所有分布（C(n,k)≤5000），跳过约束验证 |
| LLM 审查 | 可选（默认关） | 赢墩等价组内战术选择 | 成功率差 ≥0.35（一边倒）跳过审查 |

**可选引擎共 7 种**：llm / mcts / dd / perfect / tiered / alphamu / dd_alphamu_llm（默认）。

**支撑层**：

- 采样器：均匀采样 + L0(MH 修复) / L1(主从软约束) / L2(放宽 HCP±2、suit_min 减半) / L3(仅 void) / 兜底(选违反最少) 五级回退链；`_check_feasible` 可行性预检防空转。
- 约束系统：v1.68 统一 LLM 转译生成（负面推断 / 扣叫→suit_controls / 4NT 答叫→min_keycards），`_merge_constraints` 单调收紧合并，中局 `_reduce_constraint_for_played` 按已出牌扣减，弹窗与决策双展示（"叫牌约束"整手 + "最新约束"扣减后）。
- 计分制：IMP 默认（期望 IMP，考虑宕分/超墩/局况），贯穿 DD 评分、候选分组与输出。
- DDS 层：DirectDDS ctypes 直调，全局锁串行化，批量 `solve_all_boards_raw/bits`。

## 三、核心教训

1. **先问"问题在哪一层"**。飞牌最初被当作决策层缺陷，实际是采样信息层缺陷——DDS 在给定世界内已最优，"识别飞牌→干预决策"的所有变体（镜像对、敏感牌、保底、低张 tie-break）都是多余的。层找错，方案必然复杂且无收益。
2. **约束是唯一值得持续投入杠杆**。采样世界的正确性决定 DDS 结果，投入优先于任何"打牌启发式"。用户原话（2026-08-26）：*"如果做好约束生成，加上 DDS 本身的能力，足够打出飞牌的策略。"*
3. **数学反例要早做**。临界过滤"对 make_rate 无损 / 对 IMP 有损"在 v1.67 方案文档里就写出来了，但直到追问才被当成决策依据。写进方案的数学结论应当同时回答"那还做不做"。
4. **定向/偏置采样是系统性偏见之源**。历史两次引入两次否决，均匀采样是不可妥协的基线。
5. **不为"已有代码"保留功能**。BeliefTracker、规则库、endplay 链路都是"引入—论证—废弃"的完整循环。判断标准是立场与收益，不是删除成本；无害不等于无负担（配置面、接口链、文档、测试都要维护）。
6. **外部库语义要逐字验证**。`solve_board` 方向（curplayer vs first）、DDS 线程安全、`deal.first` 语义（perspective vs actual_turn）、DDS equals bitmask——每个都造成过引擎级事故。
7. **论文复现要逐条对照**。αμ 初版 Min 节点合并语义错误、根节点选牌偏离论文、M=2 在 13 张牌复杂度过高（论文 §5 实验目标是 32 张牌残局）——对照论文 PDF 逐条修正后才稳定。
8. **"剔除平凡样本"听起来像工程提速，实际是目标重定向**——它悄悄把"全局期望"换成"做成边界期望"，语义变更必须经用户确认。

## 四、目前的困难

1. **紧约束下可行解稀疏**：双约束场景合法世界占比低至 0.004%~0.012%，MH 导向性搜索难命中稀疏解，靠主从软约束兜底；L2 放宽（HCP±2、suit_min 减半）后约束区分力基本丧失（放宽后 100% 通过）。
2. **中盘 strategy fusion 未根治**：αμ 在 >8 张牌强制 M=1（退化为 PIMC），中盘仍靠 DD + 可选 LLM 审查弥补，而非算法层面解决。
3. **防守方信息利用不足**：扣叫（suit_controls）/ 关键张（min_keycards）约束已提取合并但不参与采样校验（v1.68 决策，庄家/明手手牌已知，这类约束只对防守采样有意义，现集中攻坐庄）；张数/姿态信号只进 LLM prompt，不进采样权重。
4. **LLM 审查性价比存疑**：延迟大（思考模式 60-90s）、偶发空输出、多数时候只是验证引擎选择而非改进；防守方决策占一半但审查覆盖不全。
5. **约束转译质量未经实战基线验证**：LLM 从含义文本转译约束的准确率没有量化基准，端到端三条交互路径（正常 AI 叫牌 / 关闭 AI 解释 / 外来牌局模拟补全）待 UI 验证。
6. **长线计划连贯性**：αμ+LLM 的 plan 机制已有步骤跟踪与失效检测，但跨墩战略一致性仍弱。

## 五、可能的解决方案（按优先级）

1. **坐庄信息增强（当前主线）**：
   - 张数/姿态信号的采样级利用（信号证据 → 采样权重，而非仅 prompt 注入）；
   - 罕见分布的充分采样（增加样本数、残局精确枚举、收紧约束缩小世界集）；
   - 约束转译链路的实战验证与基线对比。
2. **防守打牌研究（下一战役）**：
   - 恢复 `_check_constraint` 中 `suit_controls` / `min_keycards` 两段校验；
   - `_reduce_constraint_for_played` 补齐中局扣减折算——已兑现承诺（该门 A/K 已出、关键张已出够数）应从约束中移除，避免残局采样被已兑现承诺卡死；
   - 确定 RKCB 答叫"1或4 / 0或3"二义性的取值口径。
3. **采样算法层（中长期）**：序贯重要性采样 / MH 提议分布改进；粒子滤波是长期方向但需先解决重采样问题（避免重蹈 BeliefTracker 覆辙）。
4. **解释层**：飞牌结构识别只落在展示层（面板标注"这里在飞 Q"），不干预决策。
5. **长线计划连贯性**：借助 αμ+LLM 已有的 plan 机制（步骤跟踪 + 4 条件失效检测）逐步强化。
