# 坐庄决策：双明手全知偏差与"单明手精修"通用方案

> 2026-09-10 方案讨论稿（尚未实施）
> 触发牌例：3NT 南庄，西弱二 2♠ 首攻 ♠J，第一墩南盖 ♠K 败着，应让过 ♠2。

---

## 一、触发牌例

- 定约 3NT，南坐庄；西弱二 2♠（6 张♠）。
- 庄/明：南 ♠KQ2 ♥A32 ♦A432 ♣QJ2 | 北 ♠43 ♥K54 ♦K65 ♣AT987。
- 第一墩：西♠J、北♠4、东♠6、**南出♠K**（系统所选），南赢；正确应让过 ♠2。
- 引擎当时输出：`♠K(88.0%)、♠Q(88.0%)、♠2(67.4%)`（make_rate 做成率格式）。

**正确的实战打法**：第一墩跟♠2 让过，保留 ♠KQ 双止张；否则止张只剩 Q，庄家建立红花/♣ 赢墩必然让东上手，东穿 ♠、西长♠ 兑现 → 宕牌。防守方计划即"让东家在黑桃用光前上手、飞死南的黑桃结构、靠西长黑桃宕牌"。

## 二、根因定位（先澄清目标口径的误判）

初版直觉认为"决策目标是平均赢墩，才看不到让过价值"。**核实后不成立**：

1. 系统已有 `make_rate`（做成率）口径，`DD_SCORING_MODE` 可切换 avg_tricks / imp / make_rate，界面上第一墩的 `88.0%` 正是 make_rate 格式——**做成率口径已启用，仍选了 ♠K**。
2. 因而核心缺陷不在目标函数，而在**评估器本身**：DDMC 对每个候选在采样世界上做**双明手全知求解**（solve_all_boards），庄家在评估过程中"看到"全部未知大牌的位置。全知视角下：
   - 烧一个止张可以被"精确推算"兜回来，多数分布照样做到 ≥9 墩 → ♠K 的全知做成率反而高于让过（88% vs 67%）。
   - "保留进手结构、忍让、避免烧敌方长套穿越"这类**只在信息不完整下才有价值**的打法，双明手评估系统性抹平。
3. 换任何目标函数（avg / imp / make_rate）都无法修正，因为误差源头是"评估世界时泄露了未知信息"。

**结论：这是 DDMC Strategy Fusion 缺陷的又一种表现形式**（评估时已知分布，决策时实际不知）。项目已有应对手段 αμ 搜索（残局 ≤8 张启用、Max 节点强制全世界同一选择），但第 1 墩为 13 张，αμ 不覆盖。这不是某个花色的个案，而是"中盘/首攻阶段 DDMC 全知评估"的结构性问题——**修正方向必须是通用评估改造，而不是给黑桃/让过这种具体场景加规则**（用户明确反对受限式修正，且 6S 清将研究已证明 avg≠决策口径、教训文档已证明过滤类局部修补无效）。

## 三、通用方案

不做"某个花色应该让过"的规则。三条通用、彼此互补的路径，推荐 **方案 A 为主、方案 B 为辅、方案 C 为前提**。

### 方案 A：对 top-N 候选做"单明手精修"评估（主）

思路：DD 采样全知评估 **只用于粗筛 top-N**；对 top-N 再跑一遍**实战视角的可成率**——假设庄家只掌握公开信息（己手、明手、已出牌、叫牌约束、首攻信息），以受约束采样世界为环境，用 rollout/有限树把牌局"真实打完"，统计实战可成率。烧结构、断进手的牌在实战模拟里真的宕，让过/保留止张自动胜出。

对应业界参照：GIB 第二墩起切真正的单明手求解器；Wbridge5 用 αμ（本项目已有，仅残局）。**方案 A 是把"非全知评估"从残局扩展到中盘/开局的轻量做法**。

关键设计点：

1. **粗筛**：沿用现有 DDS 全知评分取 top-N（建议 3-5 张，DDS 一次给全部候选，零额外成本）。
2. **精修评估器（实战模拟）**：
   - 每个 top-N 候选，在现有约束采样世界集上（或复采样 M 个世界）执行"实战打牌模拟"：
     - 庄家/明手：按单一视角启发式出牌（可靠的已知信息决策）；
     - 防守方：按防守启发式（或随机加权），可注入信号模型（已有 `signals.py`）。
   - 复用项目已有基础设施：`bridge/mcts/rollout.py`（HeuristicRollout / RandomizedRollout）、`sampler.py`（约束采样）、`dealer.py`。
   - 统计"庄家方在实战模拟下赢墩 ≥ 定约需要"的占比 = 单明手可成率。本牌例预期：♠2 可成率显著高于 ♠K。
3. **合并决策**：单明手可成率为主排序；仅当差距不足（如 <2%）回退 DDS 均值/imp，避免失真。
4. **成本控制**：只精修 top-N × 有限模拟次数（如每张 50-100 次 rollout）；rollout 天然远快于 DDS，不放大根因里的求解瓶颈。
5. **适用面**：庄家/防守均可用（防守精修用同构模拟，方向取最小化）。

风险评估：

- rollout 策略质量决定评估可信度——策略太弱会系统性低估所有路线的可成率（但通常仍保留正确排序；本项目已有 rollout 启发式经验）。
- 时间预算：中盘每拍 +0.5~1.5s 可接受；需做自适应（关键墩加大模拟、平凡墩跳过）。
- 与现有 8飞9砸/流程/接应干预的交互：精修评估产出推荐后，飞牌等既有管线仍可覆盖其决策——保持"评估层"与"干预层"解耦。

### 方案 B：PIMC 决策鲁棒性惩罚（辅）

思路：不做第二评估器，而是给 DDS 全知评分加一项**跨世界鲁棒性度量**。对每个候选，观测其赢墩在"不同未知关键大牌位置"下的分布：

- 若候选的可成性对关键张位置敏感（烧掉结构的牌往往在若干分布里直接宕、其余分布大赢），按尾部风险降权；
- 度量可复用现有 paired 差异统计与 `max_tricks - min_tricks`（6S 清将研究里已积累的 spread 概念），做成**通用惩罚项**而非固定阈值规则。

优点：纯打分层改造、无第二模拟器、成本低。缺点：仍是"间接代理"，比不上真打一轮；且"关键张位置"的定义要小心不做成黑桃特例。作为方案 A 的兜底/先行验证。

### 方案 C：采样先验加固（前提，且应当先做）

评估可信度的地基是采样世界贴近真实。两条明确的补强：

1. **叫牌约束**：西 2♠ 弱二 = 6 张♠ 已应在约束库（`bid_constraint_library` / `_seed_constraints`），需验证首攻墩是否真的应用（本牌例输出带约束与否需查）；没生效则让过价值被非真实分布稀释。
2. **首攻信息**：首攻 ♠J 隐含"引牌方黑桃结构/无更高相邻大牌"等贝叶斯先验，注入采样（`sampler.py`）后世界分布显著更真。
3. 已有 `约束生成优化.md`/`叫牌约束提取优化方案.md` 讨论沉淀，方案 C 与其衔接，不重复造轮子。

## 四、实施步骤建议

1. **验证 C**：确认本牌例首攻墩采样是否应用西弱二约束；未应用则先修（数据地基，改动小）。
2. **原型 A**：独立脚本对第一墩三候选跑单明手精修模拟，量化 ♠K/♠Q/♠2 的可成率差，验证"精修能翻转排序"（本牌例是决定性判据）。
3. **接入 A**：top-N 精修作为 `dd_search` 决策尾部步骤（或 play_service 封装），先默认关闭、开环境开关，跑复现集回归。
4. **可选 B**：若 A 成本不可控，退化用 B（鲁棒惩罚）先行，A 作长期目标。
5. 与飞牌干预管线联测：确保精修推荐仍可被飞牌强制动作覆盖（保留现有决策链层级）。

## 五、开放问题（评审点）

1. 精修模拟的首攻后信息范围：明手牌可见、庄家视角用哪些"公开推理"（约束 + 首攻信号），是否引入信号模型。
2. 防守方模拟策略等级：纯启发式 vs 随机加权 vs 轻 αμ；等级越高评估越准但越贵。
3. "可成率"对超墩/MP 无感——是否保留 imp 权重做二级排序。
4. 方案 A 的精修范围扩展到防守方时，是否复用同一模拟器（方向取反）。
5. 与 LLM 升级（Tiered 的 critical 检测）如何分工：单明手精修是"DDS 侧的非全知替代"，LLM 是"非全知推理"，两者可能冗余——但精修更可控可测。
