## 一、规则层在出牌链路中的位置

规则层是**叠加在引擎结果之上**的：引擎先算 `candidates`，规则层只做"改写或放行"。

```
/api/play/ai-play
      │
      ▼
PlayService.get_ai_play(use_dd, use_perfect, use_alphamu, ...)
      │  引擎分流（白名单见 api/main.py KNOWN_PLAY_ENGINES）
      ├─ use_perfect ─────► _perfect_play        ✗ 无规则层
      ├─ use_alphamu ─────► _alpha_mu_play        ✓ 规则层（结构来源＝模板法）
      ├─ use_dd（默认）───► _dd_play              ✓ 规则层（结构来源＝探针法）
      └─ 兜底 ────────────► _llm_play             ✗ 无规则层
      │
      ▼ result{card, reasoning, full_output{mcts_stats{candidates}}}
      │
      ▼
_intervene(state, result, FINESSE_RATIO)          # play_service.py:1488
      │  ← 规则层总入口
      ▼ result.card（可能已被改写，改写痕迹写入 full_output）
```

> **调用点**：`_dd_play` 内（`play_service.py:2856`），且仅当 `DD_FINESSE_ENABLE` 为真。
> `DD_FINESSE_ENABLE=False` 时 DD 引擎**完全不带规则层**（探针一并关闭，不做任何飞牌管理）；αμ 不受该开关影响。

**结构来源按引擎分流**（`_detect_finesse_struct`）：

| 引擎 | 结构来源 | 判据 |
|---|---|---|
| DD | **探针法** | `full_output` 含 `finesse_probe` 键 → 只信探针；探针为空＝无结构，**不回退模板法** |
| αμ | **模板法** | 无 `finesse_probe` 键 → 回退静态间张识别 |

## 二、总入口闸门与分支序（`_intervene`）

```
_intervene(state, result, ratio)
  │
  ├─ ① current_player ∉ (declarer, dummy) ───► 放行（防守方出牌完全不干预）
  ├─ ② _is_discarding(state) ────────────────► 放行（垫牌直接信任引擎）
  │
  ├─ ③ 领出（_is_leading：本墩尚无任何牌）
  │     │  领出＝新墩开始 → 作废上一墩登记：
  │     │     finesse_flow.clear() + finesse_flow_extra.clear()
  │     │     （组合飞废弃对象随登记同灭）
  │     │
  │     ├─ 分支1（9砸·完全独立）：FINESSE_EIGHT_NINE_ENABLE?
  │     │      hit = _garrison_lead(state, result)
  │     │      hit is not None → return hit        ← 先命中先赢
  │     │
  │     ├─ FINESSE_DEFER_ENABLE == False → return result（只关飞牌，不影响 9砸）
  │     └─ 分支2（飞牌介入）：return _finesse_lead(state, result, ratio)   §三
  │
  └─ ④ 跟牌
        ├─ 分支1（9砸·跟牌侧）：_garrison_follow(state, result)
        │      hit is not None → return hit
        ├─ FINESSE_DEFER_ENABLE == False → return result
        └─ 分支2（接应链）：                                           §四
              fs = _detect_finesse_struct(state, result)
              fs = _registry_finesse_struct(state, fs)   ← 并入本墩登记
              forced = _finesse_commit_check(state, fs)
              forced 非空 → _apply_finesse_commit(state, result, fs, ratio)
              return result
```

> **分支关系**：9砸 与飞牌介入是**并列**分支，判据互不依赖，按序裁定、先命中先赢；未来新分支（如忍让）同接口并列加入。
> **登记生命周期**：`finesse_flow` / `finesse_flow_extra` **只存活本墩**（领出即清空）——v1.77 已删除跨墩续飞状态机。
> **跨墩双飞如何维持**：登记虽只存活本墩，但"是否为双飞"**不靠登记继承**——下一墩 `_probe_finesse` 重新探测：K/9 都未现身时，强信号门（v1.97+ 同花色 ≥2 达标对象合并）再次把二者合并成双飞（保 K、废弃 9、Δ 加和），故第二轮仍适用大牌判据（min(对象K,废弃9)=9，♦Q 牌点12>9 → big=1 出 ♦Q）。**仅当 9 已现身/被打下、对象窗滑掉 9 后**才退化为单飞 K。每轮仍须重过启动门控，不过则尊重引擎。
> **跨分支通信**：`finesse_flow_extra["九砸"]` 供 9砸分支引小后由接应消费；`nine_cash_bank` 是 9砸分支**私有跨墩状态**（顺序砸 AK 的连拔登记）。

## 三、领出分支：`_finesse_lead`

```
_finesse_lead(state, result, ratio)
  │
  ├─ A. 稳成前置（v1.89 改动C；口径/阈值 2026-09-20 调整）
  │     _top1_make(candidates) ≥ FINESSE_NEC_MAKE_HIGH (0.85)   ← 只看**引擎 top1**
  │     → 直接退让（省掉伙伴侧完整 DD search——它是最贵的开销）
  │       例外：引擎 top1 恰在本侧飞牌花色时**登记本墩接应**（稳成不挡流程内接应）
  │
  ├─ B. 建结构池（改动A·留栈）
  │     本侧探针 _detect_finesse_struct ＋ 伙伴侧探针 _probe_partner_finesse_struct
  │     → 合并；逐条 (对象,引牌) 过 _probe_finesse_ok（确定性结构判定）→ 通过者入池
  │     → 同 (花色,对象,侧) 多引牌按**押桶成分档**定代表（v1.99+，0.02 粒度、
  │       同档按 Δ 决胜；模板法无押桶成回退引擎值档）
  │     → struct_stack[s]：同花色**全部**代表条目保留（Δ 降序），不剪枝为单条
  │        （Δ 只是"进池门票"，价值裁决交给门控＋终选）
  │
  ├─ C. 引擎一致（v1.99+ 收紧）
  │     引擎 top1 已在**本侧飞牌花色**（非稳成）→ **不再无条件服从**：
  │     该花色全部本侧未现身条目经 _subset_select 押桶成终选，可改出
  │     押桶成更高的引牌；胜者登记 finesse_flow（引擎引牌胜出则尊重）
  │     同花色但非引牌（如顶张）→ **不整体退让**，交给门控
  │
  ├─ D. 过手预检（逐条目）
  │     伙伴侧条目先求安全过手牌 _partner_overhand_action
  │       · 过手牌须排除**所有**探针结构花色（防破坏其他飞牌结构）
  │       · 失败 → 删除该条目、弹栈回退（不再整花色出局）
  │
  ├─ E. 门控（逐动作）：_finesse_launch_worthwhile(action_card, candidates, action_make)   §五
  │     分子＝动作牌价值（**押桶成**，v1.94 两侧同秤）；分母＝引擎榜首
  │
  ├─ F. 终选：_subset_select（v2.03）
  │     过闸动作按**押桶成主排序**（同门控分子口径：启动后非押注方向
  │     世界无意义，引擎混合值掺死值会稀释排序）；押桶成平票 → **较大
  │     领出牌优先**（v2.03 用户定调：领出牌 牌点 > min(对象, *废弃对象)，
  │     避开被较小/第二飞牌对象"白吃"；不区分单双飞——单飞仅一对象
  │     =min对象、领出牌必小于对象→判据失效，双飞 K/9 → min=9、♦J 即
  │     判大牌）→ 再平票 引擎决策值（make_rate 下 blended=做成率×10000
  │     +平均赢墩）；押桶成缺失（模板法条目）→ 回退引擎全样本做成率
  │     → 出第一名 ＋ 登记 flow
  │
  └─ G. 模板法兜底（αμ 无 probe）
        动作池兜底生成最小飞张小牌
```

> **αμ 引擎**走模板法（无 probe）；DD 引擎一律探针法。

## 三.1 飞牌对象窗口与滑动（`_honor_missing_of_state`）

探针要"飞"的是**缺失大牌**，但并非所有缺失大牌都监控——由**每花色独立的 3 张滑动窗口**决定。**窗口决定了"哪些牌可能被当作可飞对象"，是整条探针链的起点。**

```
_FINESSE_WINDOW_BASE = ["A","K","Q","J","T","9","8"]      # 下限 8，不全包

每个花色独立推导（各花色互不干扰）：
  window = [ 基座中该花色「未打出」的牌 ] 的前 3 张
           └─ 再剔除「己方（庄家+明手）现手持有」的牌
              （己方手里的牌不是可飞对象，**不占窗口名额** → 窗口自然下移）
  ⇒ 窗口内的牌 = 未打出 且 不在我方手中 ⇒ **必在防守方（东/西）** ← 这就是"分桶"的依据

空缺值：state.finesse_windows[suit]（每次检测探针时更新，供前端展示）
```

**滑动语义**：出一个、向下补一个。

| 该花色已打出 | 窗口（假设我方未持有） | 说明 |
|---|---|---|
| 无 | 最高三张 | 起步（基座前三张） |
| 第二张 | 第 1、3、4 张 | 第二张出 → 第 4 张补位 |
| 前两张 | 第 3、4、5 张 | 依次下移 |
| 前四张 | 第 5、6、7 张 | 到基座下限为止 |

> 具体牌面示例（A/K/Q…）会把点数写进正文，容易与"阈值声明"混淆——上表因此只用张次表述。

**关键点（易踩）**：

1. **下限是 8**——残局能飞 9/8。（早期实现基座只到 T，导致"T7 对防家 95 可飞 9 却探测不到"。）
2. **"剔除己方持有"在"未打出"之后**：我方手里握着的大牌不占名额，窗口因此更早下移到真正缺失的牌。
3. **已统一为单一规则**：v1.70 曾区分「非飞牌花色固定 [A,K,Q] 不补位 / 仅飞牌花色下滑」，现行实现**已去掉 flow / 非 flow 分支差异**——所有花色一律按上式滑动。（旧文档若仍写该区分，即为过期。）
4. 窗口只影响**探针探测哪些对象**；对象是否真正构成飞牌结构，仍由 §三 B 的 `_probe_finesse_ok` 确定性判定，并经 Δ 门票（`FINESSE_PROBE_DELTA`）。

## 四、跟牌分支：9砸·跟牌侧 ＋ 接应链

### 4.1 `_garrison_follow`（9砸·跟牌侧）

```
_garrison_follow(state, result)
  │  介入口径：引擎当前决策牌为该跟牌花色的"间张"（10 ≤ rv < 对象）
  ├─ 无领出花色 / 当前牌非领出花色 / 非间张 ──► return None（交回接应链）
  ├─ _garrison_target(state, lead_suit, candidates) 为空 ──► None
  ├─ A 不在当前跟牌方手 ──► None（跟牌无法砸）
  ├─ _top1_make ≥ 0.85 ──► None（稳成线退让：引擎 top1 已 ≥85% 成约）
  └─ 命中 → 改出该花色 A
       （缺Q/J 持 AK 且 K 在联手未出 → 登记 nine_cash_bank，下墩连拔 K）
```

### 4.2 接应链（`_finesse_commit_check` + `_apply_finesse_commit`）

```
fs = _detect_finesse_struct(state, result)     ← 本墩探针
fs = _registry_finesse_struct(state, fs)       ← 并入本墩登记（含组合飞废弃对象）
     │
     ├─ 严格只信当墩探针：判空即无结构，**不用 flow 补构**
     │   （v1.71 曾用 flow 补构，用户否决"补构式修改"后撤销）
     │
     ▼ forced = _finesse_commit_check(state, fs)          # 返回 (接应牌, 说明) 或 None
     │
     ├─ None ──► 尊重引擎（这是**尊重引擎的唯一途径**）
     │
     └─ 非空 ──► _apply_finesse_commit(state, result, fs, ratio)
                  │  与 _finesse_commit_check **共用同一传入 fs**
                  │  （不内部二次检测——二次检测会静默吞掉已确认结构）
                  └─ 退让裁决 _finesse_commit_ratio_ok               §六
                       True  → 强制接应（改写 card）
                       False → 尊重引擎
```

## 五、启动门控 `_finesse_launch_worthwhile`

分母＝引擎榜首；分子＝**动作牌在押注方向半桶的做成率**（探针「押桶成」，v1.94 两侧同秤）。

```
top_make = 榜首候选 scores 中 ≥ tricks_needed 的占比
  │
  ├─ top_make < FINESSE_NEC_MAKE (0.50)          ← 契约必要：不飞没机会
  │     └─ 动作/榜首 ≥ FINESSE_NEC_MIN_RATIO (0.50) → 必飞
  │        （不足则落下一档）
  │
  ├─ 动作/榜首 ≥ FINESSE_NEC_RATIO (0.70)         → 启动
  │
  └─ 否则                                          → 退让（尊重引擎）
```

**⚠️ 稳成线（`_top1_make` ≥ 0.85）不在此处**——已由 `_finesse_lead` 入口前置短路（§三 A）。

## 六、接应三层判据 `_finesse_commit_ratio_ok`

数据源＝**跟牌接应探针** `full_output["finesse_probe_follow"]`（按登记对象在东/西余手分桶，全部候选牌桶内做成率，**零额外 DDS**，蹭主搜索世界）。
`b_bucket` ＝「非强制牌的引擎最优候选 `top_alt`」在**登记方向**桶内的做成率。

```
b_bucket ≤ FINESSE_COMMIT_DIE_PCT (0.05)  且 强制牌桶内 a_bucket > 0
      → 定约不飞即死 ⇒ **强制接应**            （6NT 型：西桶 ♦A=0）
b_bucket ≥ FINESSE_COMMIT_ALIVE_PCT (0.40)
      → 定约不依赖这墩飞牌 ⇒ **退让引擎**      （B26 型：西桶 ♦A=0.542）
灰色区 / 桶数据缺失 / 双零死局
      → 落 v1.93 口径兜底 ↓
  ┌─ ① 引擎榜首与强制牌同花色 且 榜首 rank < 对象（间张，引擎也在飞）
  │      → 采信引擎 top1
  ├─ ② 同花色 但 榜首 rank ≥ 对象（顶张/盖张，引擎在兑现而非飞）
  │      → **不采信**，落 ③
  └─ ③ 比值退让 _finesse_ratio_ok(ratio = FINESSE_RATIO = 0.75)
        段1 做成率优先；段2 决策值兜底（scoring_val→avg_tricks）
```

> **为什么 ①/② 要分 rank**：v1.87 曾"同花色即采信"，但 6NT 案中榜首 ♦A（兑现）与强制牌 ♦J（飞张）**同花色而语义相反**，采信等于用顶张替掉飞张。
> **为什么灰区不回退到统计量**：B26 教训——「桶内完胜比」在"不飞仍活"的世界是**假信号**（不飞仍活时桶内 0.542，比值 1.85 看似完胜，实则全局期望更低）；区分判据是"押对世界榜首桶内值是否为零"。

## 七、9砸分支（完全独立于飞牌介入）

**判据只用两种情况**（2026-09-18 用户定调直白化，`_garrison_target`）：

```
联手张数 ≥ 9  且  对象未现身
  ├─ 缺 Q 持 A+K  → 砸 A，并登记 nine_cash_bank 下墩**连拔 K**
  └─ 缺 K 持 A+Q  → 砸 A（先砸后飞）
其余一律不走 9砸（如 AKQ 顶张齐全 → 交回引擎自然兑现）
```

`_garrison_lead` 流程：

```
① 连拔检查（nine_cash_bank，**不受稳成线约束**——连拔是已启动流程的完成动作）
     本墩领出该花色 且 对象未现 且 本方可出 K → 改出 K 连拔
     K 在对侧 → 引最小小牌 ＋ 九砸标记（伙伴第三家超吃完成连拔）
② 稳成线退让（_top1_make ≥ 0.85 → 不砸）
③ 独立扫描全部花色（按联手张数降序）→ _garrison_target 判据
     A 在领出方手 → 直接砸 A（缺Q持AK 登记 cash_bank）
     A 在伙伴手   → 引最小小牌 ＋ 九砸标记（伙伴超吃）
```

> **为什么 9砸 必须独立**：满手大牌时 DD 完美防守下大牌位置**互偿**（探针 Δ 天然趋零，东/西差异仅 8.62 vs 8.54 量级）——这是**信息论上限**，不是探针缺陷。9砸判据**本就不需要位置信息**，故独立分支零漏检。

## 十、八条易踩陷阱

1. **DD 跟牌时无探针**：`_probe_ok` 要求「本家领出」（`dd_search.py`），跟牌时 `finesse_probe` 键不存在 → DD 结构识别**回退模板法**。口径与领出侧不对称。
2. **接应不做二次检测**：`_apply_finesse_commit` 必须与 `_finesse_commit_check` 共用同一 `finesse_struct`；内部重新检测会静默吞掉已确认结构。
3. **接应禁止用 flow 补构**：`finesse_flow` 只管本墩登记与 9砸 通信，**不得**当作接应结构来源（v1.71 已撤销）。
4. **9砸 受稳成线约束，但连拔不受**：`_garrison_lead` 流程为「① 连拔检查（**不受稳成线**）→ ② 稳成线退让（`_top1_make` ≥ 0.85 则不砸）→ ③ 判据扫描」，故 9砸 本身在引擎 top1 已 ≥85% 成约时会退让，连拔作为已启动流程的完成动作则豁免；两者都不走比值门控。
5. **窗口期启动不走 `FINESSE_RATIO`**：启动依据是探针结构 Δ（位置敏感），不是单步比值（顶张恒高于飞张小牌，用比值会扼杀全部主动启动）。
6. **登记只存活本墩**：`_intervene` 领出时 `clear()`；跨墩续飞状态机已于 v1.77 删除，**勿再引入**。
7. **垫牌不处理**：`_is_discarding` 直接放行。
8. **"顶张方/非顶张方"概念已废弃**（v1.76 用户定调）：飞牌可行性唯一判据是 `_probe_finesse_ok`。**勿再引入该概念**。
