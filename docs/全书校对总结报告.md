## 二、校对方法

1. **双通道验证**：先用 PyMuPDF 提取 PDF 文本层做初筛比对，再对存疑处渲染 300 DPI 图像裁片亲验。
2. **花色符号必须看图**：PDF 文本层的 ♣/♠ 均映射为黑色字形无法区分，OCR 常将两者混淆；"≥"常被 OCR 误识为">"或"~"。凡涉及花色符号与点力范围符号的修改一律以 300 DPI 图像为准。
3. **逐处保存 + 进度持久化**：每验证/修复一处立即保存文件并更新 `_校对进度.md`，防止上下文压缩或会话中断导致工作丢失（前期曾因此损失第十三章的部分修复）。
4. **同文件 Edit 串行执行**：避免并行编辑竞争导致内容损坏。
5. **表格结构比对**：对表格类内容除逐格比对外，还核对行列顺序、表头与合并单元格（PDF 表格经 OCR 后列错位是高频错误）。

## 五、典型错误类型分类

1. **花色符号错误**（最高频）：♣/♠ 互混、漏花色（如表1-6 漏♣、原则句漏"♠"）。
2. **点力符号错误**：印刷"≥"被 OCR 为">"或"~"（第十一章约 20 处、第八章 2 处、第十二章 1 处）。
3. **表格结构错误**：列错位（表1-2）、孤儿行、整行/整块手牌与解说错位（表12-3 X 行 8 项全错、第十一章表 11-5/11-6 错位行）。
4. **手牌实例错误**：张数错（5张↔6张）、花色分配错、应叫叫品错（1♣实例1应叫1♥→1♠）。
5. **漏字/漏句**："1♥开叫后"漏"1♥"、1♥ 节整缺 6 条应叫解说、第十三章例44 漏♠牌张。
6. **结构性差异**：附录一顺序与虚构章标题；第六节"不急于"经图证确认为 md 正确（OCR 漏"不"），属误报未改。

## 六、经验教训

1. **PDF 文本层不可单独采信**：自定义字体映射会打乱花色符号，OCR 对"≥/~/>"、♣/♠ 的误读率很高，关键差异必须图像亲验。
2. **进度持久化是必需品**：长会话必然经历上下文压缩，细粒度状态（逐条 diff 清单）会丢失；`_校对进度.md` 的"每处即更"规则使第十三章返工仅限单个牌例。
3. **先验证后修改**：多处"疑错"项（第六节"不急于"、表5-46/5-55）经图证实为 md 正确、OCR 有误——不预设 md 有错可避免引入新错误。
4. **验证图可复用**：`_tmp_*` 目录的 300 DPI 裁片在返工时直接可用，本次全书完成后已随进度文件一并清理。
