## 修订说明（2026-09-08 · v1.70）

本轮飞牌干预重构，以下旧结论**已作废/已变更**，阅读本文旧章节时注意：

1. **拖延策略整体废弃**（§二 全节作废）：坐庄方明手牌可见、防守方为采样平均，单步贪心不会因拖延换花色"获得信息后改判"——拖延只有代价无收益。相关方法/配置已删除。
2. **DD 引擎飞牌识别改用探针法**（§一 模板法仅存于 αμ 引擎）：probe 存在即采纳、判空即无结构，**不回退模板法**；Δ≥`FINESSE_PROBE_DELTA`(0.4)。
3. **新增"探针检测 + 显式验证"两层**：可飞性校验（`_probe_struct_playable`）要求 <对象 且 ≥10 的间张 + >对象 的上方控制，过滤"位置敏感但无张可飞"的假阳性（如 ♠AK+xx 缺 T）。
4. **探针监控 = 3 张滑动窗口**：默认 AKQ；仅飞牌花色（finesse_flow）在窗口内大牌打出后下滑补齐三张（K出→AQJ、A出→QJT）；非飞牌花色固定 AKQ 不往下移。
5. **新增启动路径**：窗口期主动启动（`_probe_lead_finesse_prefer`，不走 0.95 比值，用探针结构本身）+ 顶张侧过手启动（`_apply_lead_transfer`，队友侧同口径探针 + `_cash_reentry` 过手）。
6. **流程标记对象化**：`finesse_flow` 存对象 int，清理只按"对象现身/花色已死"，不再被当墩探针判空误清。

## 〇、设计哲学：引擎分工与护栏定位

1. **概率引擎（DD/αμ）的能力边界**：剥光投入、挤牌、擒将等"唯一路线"打法引擎已能处理（所有世界里正确选择一致，MC 平均自然收敛）；引擎真正的盲区是**策略分裂（strategy fusion）**——飞牌是典型：K 在东路线 A 赢、在西路线 B 赢，两条路线互斥，PIMC 按期望融合后必在一半世界错。
2. **人类飞牌元规则 = 护栏**，分两层：

   - **决策层（软干预）**：拖延/时机。只输出"换花色观望"，需过比值/时机关卡，不硬占优。

   - **执行层（硬规则，零风险）**：强制接应、8飞9砸、顶张方回手、继续飞牌。方向/进手/接应错了必输，与概率无关，规则优先直接纠。
3. **拖延的两层价值**（用户原话归纳）：

   - ① 拖延以发现更多分布信息（8飞时把 K 位置从 50% 猜测变成可观察）；

   - ② 引发飞牌花色后的正确处理，避免"引发飞牌遇有利分布、却因引擎原因误处理"。
4. **胜负观**：桥牌不是对理论定约，而是对其他牌手；叫不成的定约别人大概率也打不成，多赢就是胜出（支撑"全输局选高潜力牌"研究方向）。

## 二、拖延（决策层 · 软干预）——【2026-09-08 整节废弃】

> **已废弃**：坐庄方明手牌可见、防守方为采样平均，单步贪心不会因拖延换花色"获得信息后改判"，拖延只有代价无收益。`_defer_candidates`/`_is_danger_suit`/`_is_finesse_struct_card` 与入口领出拖延分支、配置 `FINESSE_RATIO_RISK`/`FINESSE_LOSE_TRIGGER`/`FINESSE_DEFER_WIN_MIN` 已删除。下表仅存史。

| # | 问题                                                 | 最终方案                                                                                                               |
| - | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 1 | 领出是否引发飞牌，判定次序混乱（先看跟牌）                              | 领出时**独立判断**：决策牌是否为飞牌结构花色牌，**不论大小**（Q/J/T 领出同样引发），记录判定；再考虑拖延                                                        |
| 2 | 8飞9不飞的适用范围与判据                                      | **通用原则**（不限将牌/边花）：联手 ≤8 → 飞；≥9 且 **A+K 双顶张都在我方** → 砸（双顶张不齐，9 张也飞）。9 张缺 K 持 AQ → **先砸后飞**（拔 A 砸，K 未落再飞 Q）。将牌花色不参与拖延 |
| 3 | 比值不统一（0.9/0.8/0.95 并存，改易漏）                         | 统一 **FINESSE\_RATIO=0.95**（DD 三种计分制 / αμ 共用）；结构牌全输占比 ≥80%（无望花色）放宽到 **0.90**                                        |
| 4 | **拖延时机**（最关键的收敛，2026-09-05）：无谓拖延长期制造问题，这副 ♦ 牌根本该早飞 | **两层门控**（见下节专述）                                                                                                    |
| 5 | 拖延烧护张：拖延牌所在花色联手 ≤4 无 A/K，飞败后敌方长套兑现全输               | **危险花色**（联手≤4 且无 A/K 控制）不可作拖延牌；全部候选都被排除则直接启动飞牌                                                                     |
| 6 | 拖延烧进手：♣K 这种唯一回手桥被拖延打掉                              | 曾实现"rank≥Q 不作拖延牌"——**已撤销**（不通用：9 张宽配打 Q 无损，绝对 rank ≠ 进手）                                                           |
| 7 | 将牌被作为拖延/绕路对象                                       | 领出拖延决策中**剔除将牌花色**（将牌需积极处理：清将/飞将优先）                                                                                 |

### 拖延时机：两层门控（核心）

```
① 张数门控：飞牌花色联手 ≥9 张  → 禁止拖延
   （9砸为正 EV 确定打法，拖延纯损；对有将定约此门主要作用于无将）
② 成败敏感度：联手 ≤8 张时，结构牌全输占比 ≥ FINESSE_DEFER_LOSE_MIN(0.2)
   才允许拖延（飞失败风险显著，信息增益才有价值）；
   低于门槛说明飞牌基本稳成 → 早飞，禁止无谓拖延
```

- 唯一允许拖延的窗口：**8 张（必须飞）且飞失败风险显著**

- 拖延动作仍受：比值 ≥0.95/0.90、危险花色排除、将牌剔除三重约束

## 三、执行层（硬规则 · 零风险）

| # | 问题                                         | 最终方案                                                                                                                     |
| - | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 1 | 队友已启动飞牌，本家却拔 A 烧进手                         | **强制接应**（`_finesse_commit_check`）：同伙本墩已出该花色 ≤9 牌 + 本家有飞张(≥T,<对象) + 有更高顶张(A/K) → 强制出飞张压制顶张                                |
| 2 | 9砸后回手缺失：顶张方（持 A/Q）自己领出该花色（大小牌都不行），K 决定方向错误 | **顶张方判定**（`_has_high_suit_cards`：领出方手中含 A 或 Q）：9砸后阶段（A 已砸、K 未现）顶张方一律**不得自领飞牌花色**，强制换花色回队友手                               |
| 3 | 回手牌选择武断、依赖引擎得分                             | **两手牌确定性判定**（`_nine_cash_reentry`）：选"队友稳赢"的无关花色（队友该花色最大牌 R\_p > 敌方潜在最大牌 threat= 未现于两家/已出的最大），在候选小牌(≤9)中取最小让渡牌；无稳赢花色则尊重引擎 |
| 4 | 回手成功后队友仍出锁死牌（♥2 9-9 封顶）而非飞牌（♦2 8-11 有机会）   | **继续飞牌**（非顶张方领出）：飞牌流程已启动，引擎选了无关花色 → 强制改出飞牌花色最小飞张（规则优先，不走比值）                                                              |
| 5 | 9砸后 A 已砸、榜首间张时"主动出最小牌喂 K"                  | **已删除**：A 砸后交给引擎自行决策（2026-09-02 按用户要求移除）                                                                                 |

## 五、管线总览（代码路径）

- 入口：`_apply_finesse_tactics(state, result, ratio)`（DD/αμ 共用）

  - 垫牌 → 不处理，信任引擎

  - 领出 → `_apply_lead_finesse_check`：结构识别（探针+可飞性校验）→ 空结构时先走流程延续、再试**顶张侧过手启动**（`_apply_lead_transfer`）→ 9砸后分流（顶张方回手 / 非顶张方继续飞）→ 流程延续（`_apply_flow_continuation`）→ **窗口期主动启动**（`_probe_lead_finesse_prefer`）→ 尊重引擎

  - 跟牌 → `_finesse_commit_check`（强制接应）+ `_apply_eight_nine_rule`（8飞9砸 / 9砸先飞）

- 关键辅助：

  - `_detect_finesse_struct` 结构识别（DD 探针法 / αμ 模板法分流）+ `_probe_struct_playable` 可飞性校验（两路径同口径）

  - `_probe_lead_finesse_prefer` 窗口期主动启动（探针 Δ≥0.4 即启动，不走 0.95 比值）

  - `_apply_lead_transfer` 顶张侧过手启动（队友侧同口径探针 + `_cash_reentry` 过手，写 finesse_flow）

  - `_nine_cash_done` 9砸后阶段判定（played 含 A、无 K、对象 K）

  - `_cash_reentry`（原 `_nine_cash_reentry`）顶张方回手牌选择（队友稳赢）

  - `_has_high_suit_cards` 顶张方判定（持 A/Q）

  - `_combined_suit_count` 联手张数（在手+已出，与 9砸 同口径）
