# 临界样本过滤选牌方案

> 2026-08-25 定稿（实现版本：DD_SECURITY_FILTER 叠加于三种计分制之上）

---

## 一、原因：为什么需要过滤样本

### 1.1 DD 决策的本质问题

DD（双明手）引擎按给定计分制（IMP / 做成率 / 平均赢墩）对采样出的"世界"（未知牌分布样本）取平均，选全局最优出牌。但**全量样本平均会稀释选牌的关键信息**：

- 一个世界里，如果**任何合法出牌都能做成**（轻松打成），选哪张都对最终结果无差异——它在对比候选时只是"陪跑"，不提供任何区分度。
- 一个世界里，如果**没有任何合法出牌能做成**（根本打不成），选哪张都宕——同样是无效信息。
- 只有一种世界值得引擎认真决策：**存在能做成的合法出牌、也存在做不成的合法出牌**（"有输有赢"）。出牌选择在这些世界里真正影响做成与否，是选牌质量的胜负手。

### 1.2 全量平均为何有害

对三种计分制分别来看：

| 计分制 | 全量平均的缺陷 |
|--------|----------------|
| **avg_tricks 平均赢墩** | 用占比最大的"轻松打成/铁宕"世界主导排序，临界世界（可能选错就完蛋）被淹没 |
| **make_rate 做成率** | 轻松打成的世界为任何出牌都加 1，做成率趋同，候选间差异被抹平 |
| **imp 期望IMP** | 超墩/宕分的权重覆盖掉"做成与否"的硬约束，选牌可能偏好稳妥而非关键路径 |

### 1.3 目标

开启过滤后，**只保留"有输有赢"的临界世界**参与计分，让引擎把计算资源与决策权重集中在"选牌定生死"的牌型上；关闭时行为与全量样本完全一致，不影响原有三种计分制。

## 二、思路：过滤语义的定义与演进

### 2.1 最终语义（用户确认）

对每个世界，取**所有候选合法出牌**在该世界下庄家方的可达墩序列：

- `min(可达墩) ≥ 所需墩` → 任何出牌都能做成 → **剔除**（轻松打成）
- `max(可达墩) < 所需墩` → 没有任何出牌能做成 → **剔除**（根本打不成）
- `min(可达墩) < 所需墩 ≤ max(可达墩)` → **保留**（有输有赢）

其中"所需墩" = 定约做成所需总墩数（如 3NT 需 9 墩，见 `Contract.tricks_needed`）。

### 2.2 语义演进记录（防回退）

第一版实现曾采用"临界窗口"思路：定义偏差 `d = 最大可达墩 − 所需墩`，保留 `|d| ≤ K` 的世界（`DD_SECURITY_K`）。经讨论发现该语义有误：

- 它只看"最大可达墩"与所需墩的距离，**没有检查候选出牌之间的输赢分化**；
- 一个世界若"max 超墩、但另有出牌做不成"，本应是最关键的"有输有赢"样本，却被 `|d| > K` 误剔除；
- 反之，"max 恰好=所需墩、且所有出牌都能做成"的非关键世界反而被保留。

**结论：废弃窗口参数，改用"输赢分化"判定。** 实现中已删除 `DD_SECURITY_K`，仅保留独立开关 `DD_SECURITY_FILTER`。

## 三、实现

### 3.1 配置（`config.py`）

```python
# 临界分布过滤开关：叠加在 DD_SCORING_MODE 之上，不影响其三种口径本身。
#   开启后只保留"有输有赢"的分布样本（存在能做成的合法出牌、也存在做不成的）
#   ——剔掉"任何出牌都能做成"（轻松打成）与"没有任何出牌能做成"（根本打不成）。
DD_SECURITY_FILTER = False
```

开关默认关闭 = 与旧行为逐位一致（过滤分支根本不会进入）。

### 3.2 引擎层（`bridge/mcts/dd_search.py`）

**掩码生成** `_critical_mask(card_score_lists, tricks_needed)`：

```python
def _critical_mask(card_score_lists, tricks_needed):
    """按世界索引对齐的临界掩码（list[bool]）；无有效样本返回 None。"""
    n = min((len(s) for s in card_score_lists), default=0)
    if n <= 0:
        return None
    mask = []
    for w in range(n):
        vals = [s[w] for s in card_score_lists if w < len(s)]
        if len(vals) < 2:
            mask.append(False)
            continue
        mn = min(vals)
        mx = max(vals)
        mask.append(mn < tricks_needed <= mx)
    return mask
```

要点：
- `card_score_lists` 是每个候选出牌的赢墩序列列表，**按世界索引对齐**（第 w 个元素 = 第 w 个世界该出牌可达墩）。
- 逐世界收集所有候选出牌在该世界的可达墩 → `[mn, mx]` → 输赢分化判定。
- `len(vals) < 2`：只有一个合法出牌的世界无"选择"可言，判 False（本身也会被 `len(playable)==1` 的早退路径覆盖）。
- 无有效样本返回 `None`，调用方据此走"不过滤"分支。

**分数过滤** `_filter_critical(scores, mask)`：

```python
def _filter_critical(scores, mask):
    """按临界掩码过滤候选牌的赢墩序列；临界集为空时回退全量，避免无分布可决策。"""
    if not mask or len(mask) != len(scores):
        return scores
    m = [t for t, keep in zip(scores, mask) if keep]
    return m if m else scores
```

要点：
- 过滤后长度即"实际计算样本数 `samples_used`"（前端展示用）。
- **空集回退保护**：若某副牌所有世界都铁成/铁宕（无任何"有输有赢"世界），回退全量，保证仍能出牌——高频发生在打牌早期/牌型极端时，见 3.5 实测。

**接入点**：`DDSearch.search()` 采样主循环与 `_enumerate_endgame()` 残局枚举两条路径，在计算各候选 `scoring_val` 前统一生成掩码：

```python
crit_mask = (_critical_mask(
    [card_scores[str(c)]["scores"] for c in playable],
    state.contract.tricks_needed)
    if self.security_filter else None)
# ...
if crit_mask is not None:
    filtered_scores = _filter_critical(scores, crit_mask)
    scoring_val = self._decision_value(filtered_scores, state)  # 口径不变
```

关键不变量：**只替换参与计分的世界集合，不改变计分口径本身**（imp/make_rate/avg_tricks 各算各的）。过滤后走同一 `_decision_value`，保证口径一致性。

### 3.3 服务层（`bridge/play_service.py`）

`get_ai_play` → `_dd_play(state, dd_samples, dd_scoring_mode, dd_security_filter)`。`dd_security_filter` 支持**请求级临时覆盖**：收到非 None 时临时改写 `self.dd_search.security_filter`，用完在 `finally` 恢复原值——与 `dd_scoring_mode` 的既有机制一致，支持动态切换而不污染全局状态。

所有可能调用 DD 引擎的路径均透传该参数：`_dd_alphamu_llm_play` / `_dd_llm_play` / 中盘 DD 与 DD-LLM 审查分支。

### 3.4 前端（`web/`）

- `useModelSettings.js`：新增 `ddSecurityFilter` 状态，localStorage 持久化（键 `bridge_dd_security_filter`），导出 `handleDdSecurityFilterChange`。
- `SettingsPanel.jsx`：打牌引擎为 DD / DD-αμ-LLM 时，计分制下拉旁显示"临界过滤"复选框。
- `services/api.js` / `App.jsx`：`aiPlay` 请求携带 `dd_security_filter`。
- `PlayDetailPanel.jsx`：DD 统计行显示"实际计算 N 样本"，候选行显示 `实际/采样` 对比（仅当过滤真的剔除了样本时出现）；统计顶层带 `security_filter` 标记。

## 四、数学解释

### 4.1 记号与问题形式化

设采样得到 N 个世界（分布样本）`W = {w₁, …, w_N}`，候选出牌集合 `A`。定义：

- `V_a(w)`：出牌 `a ∈ A` 在世界 `w` 下庄家方的可达墩（`scores` 数组元素）；
- `T`：定约所需墩 `tricks_needed`（如 3NT → T=9）；
- 成约指示器 `λ_a(w) = 𝟙[V_a(w) ≥ T]`（"世界 w 下出 a 是否做成"）。

引擎的决策问题：按某计分制最小化/最大化一个期望型目标（平均值口径），从 `A` 中选出最优出牌。不同计分制对应不同的目标函数，但都以 `V_a(w)` 的世界平均为基底。

### 4.2 世界按 λ 的三分类（天然划分）

对每个世界 w，检查所有候选出牌的成约指示器取值：

| 类别 | λ_a(w) 取值 | 等价条件 | 名称 |
|------|------------|----------|------|
| S_win | ∀a: λ_a=1 | min V_a(w) ≥ T | 轻松打成 |
| S_lose | ∀a: λ_a=0 | max V_a(w) < T | 根本打不成 |
| S_crit | ∃a,a′: λ_a≠λ_a′ | min V_a(w) < T ≤ max V_a(w) | **有输有赢（临界）** |

S_crit 的等价条件正是 `_critical_mask` 的判定式 `mn < T ≤ mx`。数学上 λ 是布尔值，三类的唯一划分依据就是"候选出牌在做成与否上是否出现分歧"。

### 4.3 过滤的数学本质：三种口径分别论证

**① 做成率口径（make_rate）——过滤是无损精确变换**

候选 a 的做成率是 λ 的样本均值：

```
make_rate(a) = (1/N) · Σ_w λ_a(w)
```

任意两候选 a、b 的差异分解为三部分：

```
make_rate(a) − make_rate(b)
 = (1/N)[ Σ_{S_win}(1−1) + Σ_{S_lose}(0−0) + Σ_{S_crit}(λ_a(w) − λ_b(w)) ]
 = (1/N) · Σ_{S_crit} (λ_a(w) − λ_b(w))
```

S_win 与 S_lose 上的项**逐世界恒为 0**，对差分无任何贡献。过滤后：

```
make_rate_f(a) = (1/|S_crit|) · Σ_{S_crit} λ_a(w)
```

有 `make_rate_f(a) − make_rate_f(b) = (N/|S_crit|) · [make_rate(a) − make_rate(b)]`，系数 `N/|S_crit| ≥ 1` 为正常数。**结论：做成率口径下过滤不改变任何候选对的排序**——它只是把"效率因子" `1/N` 换成 `1/|S_crit|`，剔除的全是差分为零的项。从信息论看，S_crit 是做成率决策的**充分统计量**。

**② 平均赢墩口径（avg_tricks）——有意的"做成边界"偏好**

```
avg(a) − avg(b) = (1/N)[ Σ_{S_crit}(V_a−V_b) + Σ_{S_win}(V_a−V_b) + Σ_{S_lose}(V_a−V_b) ]
```

S_win 内 V_a 可能 ≠ V_b（都做成但超墩数不同），S_lose 同理（都宕但宕几墩可能不同）。**过滤会丢弃"超墩/深宕幅度"的区分信息**，把原目标函数替换为：

```
avg_f(a) = (1/|S_crit|) · Σ_{S_crit} V_a(w)
```

这不是全量 avg 的精确等价，而是一次**显式的目标重定向**：只关心"做成与否受出牌影响"的世界，超墩优化信息让位于做成可靠性。用户语义即为如此——avg_tricks + 过滤 = "在这些会定生死的世界里，平均赢墩最优"。

**③ IMP 口径（imp）——同②的非线性特例**

IMP 是墩数→分的分段非线性函数，且在做成线（第 T 墩）附近跳跃最大：

```
imp_value(a) = (1/|S_crit|) · Σ_{S_crit} IMP(V_a(w) − T, 局况)
```

过滤后 IMP 权重集中在做成跳变区域，弱化超墩 IMP 与深宕 IMP 的平滑作用——同样是聚焦做成边界的语义性定向，不是全量 IMP 的等价。

### 4.4 统计方差视角：为什么"剔除"反而更稳

对做成率口径，全量估计的方差来自 λ 的样本方差；而 S_win∪S_lose 上 λ 的**世界间方差为 0**（全部同值），它们只给分母贡献 N、不给差分贡献信号。过滤等价于把有效样本量从 N 收缩到 |S_crit|，但丢弃的全是判别值为零的世界：

- **不改变期望意义上的排序**（4.3① 已证）；
- **把"样本置信"重塑为条件置信**：`samples_used / samples` 就是 |S_crit|/N，直接反映这副牌里"决策边界有多实"——占比高说明多数世界都受出牌影响，占比低说明多数世界选牌无所谓。

阈值方面提示：全量混合恒零差分会稀释配对差分序列，过滤使统计推断聚焦于真正有分歧的世界。**注意**：|S_crit| 过小（如 kept=0）时估计噪声会放大，故 `_filter_critical` 在空集时回退全量——这是方差与信息的平衡点，见 3.5 实测。

### 4.5 一套完整示例（数学公式 → 代码表达式）

以 4×3 世界为例（3NT，T=9），三种世界分类及过滤结果：

| 世界 | V(♠A) | V(♥K) | V(♦Q) | min | max | λ 分歧 | 判定 |
|------|--------|--------|--------|-----|-----|--------|------|
| w₁ | 10 | 10 | 10 | 10 | 10 | 无（全成） | 剔除（S_win） |
| w₂ | 9 | 8 | 7 | 7 | 9 | 有（9 成/7/8 败） | **保留（S_crit）** |
| w₃ | 8 | 9 | 9 | 8 | 9 | 有（个别败/全成） | **保留（S_crit）** |
| w₄ | 8 | 8 | 7 | 7 | 8 | 无（全败） | 剔除（S_lose） |

过滤后：保留 `samples_used = 2`（w₂、w₃），`samples = 4`（原始世界数）。代码上：`_critical_mask` 对 w₂ 输出 `mn=7 < 9 ≤ mx=9 → True`，w₁/w₄ 输出 False，`_filter_critical` 据此压缩各候选的 scores 数组。

## 五、边界与注意事项

1. **不改变采样数与计分制**：过滤是叠加维度；UI 的"样本数"仍是采样数（350/324），实际参与打分的数量看"实际计算 N 样本"。
2. **kept=0 回退**：无临界世界时回退全量，此时开关无可见效果——不是 bug，是设计安全阀。
3. **过滤只会更聚焦，不会更激进**：因 `_filter_critical` 空集回退，最坏情况等于关闭。
4. **DD_SECURITY_K 已删除**：曾在 config 与构造函数中存在（窗口语义），经 2.2 论证废弃；不要以任何形式恢复。
